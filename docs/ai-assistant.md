# 仰韶 AI 助手

前台和后台使用同一 Vue / Element-Plus-X 悬浮组件，服务端通过 AI SDK 接入 OpenAI 兼容的 Chat Completions 模型。管理入口为后台一级菜单「AI API 配置」，仅主管理员可管理。

## 悬浮助手交互

前后台统一显示「AI助手」，使用已审核的小化验室机器人形象。点击角色打开对话框；鼠标或触屏拖动角色，松手后按距离自动贴靠窗口左侧或右侧。对话框可通过顶部空白区域拖动，顶部按钮、消息输入和写入确认保持原交互。拖动不会误触打开对话框，也不会发起业务请求。

位置按前台/后台及登录账号分别保存在本机，刷新后恢复。窗口缩放及软键盘改变可视范围时重新限制位置，移动端保留底部导航和安全区空间。角色和对话框顶部获得键盘焦点后，方向键可上下移动或左右贴边，Home/End 也可切换贴边。此功能仅在网页或桌面软件的内容窗口内移动，不生成系统级悬浮窗。

2026-10-11 按界面反馈放大悬浮入口：桌面角色由 80 × 88px 调整为 104 × 114px，按钮宽度 108px；手机角色由 72 × 80px 调整为 88 × 98px，按钮宽度 92px。标签字号为 13px。定位仍根据真实尺寸限制视口边界，并保留手机底部导航空间。

## 对话内容显示

前后台共用 `shared/ai/AiMessage.vue`：模型回复按 Markdown 显示标题、加粗、斜体、段落、换行、有序/无序及嵌套列表、分隔线、引用、代码和表格；用户输入保留原文。字号为 14px，并补充 macOS、Windows、Android 常见表情字体，📋、✏️、⚠️ 等 Unicode 表情随消息文本保存，无需新增图标数据库。

使用 `markdown-it` 的内置规则并关闭原始 HTML。仅显式 HTTP、HTTPS、邮件链接可点击，网页链接在新标签打开；回复中的远程图片只显示说明文字，不自动加载。表格和代码块在自身区域横向滚动，不撑开手机对话框。格式化文本不会生成按钮或业务表单，写入仍通过原有独立草稿卡片逐项核对确认。

2026-10-11 验证：消息排版、异常 HTML/链接、两端发送与草稿确认、悬浮交互共 33 项测试通过，前后台类型检查和构建通过。内置浏览器用独立本地示例验证了实际助手组件的桌面及 390 × 844 手机布局，表格和长代码只在自身区域滚动，确认按钮仍需勾选核对后启用。示例未调用真实模型或写入业务数据；当前 5183/5184 预览已同步显示改动。

## 快捷录入与连续登记

助手「快捷录入」采用逐级定位：一级菜单 → 二级菜单（后台财务有三级菜单）→ 具体录入事项/操作 → 日期 → 确认录入位置。没有下级的菜单跳过下级选择。服务端按当前身份、数据账号、字段许可、访问密码授权和全局禁止项返回所有已支持写入的入口，未授权和只读派生报表不进入录入列表。菜单名称与前后台导航对应；同页的请假类型、提成/奖金等业务分别选择，不能让模型猜。

前台数据计算页会预选已加载表格日期及刚点击/聚焦的样品序号，但仍需用户确认位置。其他菜单按公开输入格式生成专用核对表（日期、枚举、数字、必要关联记录、排班/考勤时间段等）；可直接填写，不要求输入数据库ID或JSON，也可发送文字/图片让模型生成草稿。常用入口只在本机保存菜单和动作标识，不保存客户、金额、账号数据或照片；使用前再次按当前授权过滤并确认。客户端位置提示不提供额外权限。

确认后的菜单、操作及日期保存在 `AiConversation.entryContext`，续聊时恢复。模型只取得该菜单的写入工具及必要、授权的关联查询；关联菜单不能写入。即使请求省略位置也继承服务端锁定范围，改变菜单/操作/日期必须新建会话。变更日期或菜单清空未提交表格及本地旧草稿，之前会话仍保存在历史中。范围检查也在草稿生成与实际写入事务重验，不只依靠提示词。

- 短句格式：`001 小张 60 月结款`。每行一条，每批1至5条。001是主表样品序号，不是客户编号，也不是系数计算行。
- 「填入核对表」只解析文字，不调用模型、不查询数据库、不生成草稿。核对表可修改序号、客户、金额和费用状态。
- 客户输入只匹配本账号客户名称，不返回电话等未授权联系信息。确认时核对客户档案版本并同步客户关联，不只修改名称文字。不存在的客户必须显式勾选新建，并另有客户姓名新增权限；客户创建和样品保存同事务提交，同名不覆盖。
- 常用客户和费用状态只在本次会话内、明确勾选后沿用；金额不沿用。生成后带入下一序号，切换账号、日期或新建对话清空录入上下文。序号不存在或重复时拒绝生成，不自动新增样品、不猜测id。精准序号查询不受50条明细限制。
- 「生成待确认草稿」按整批校验创建草稿，任何一行不合法则整批不生成。用户逐项核对后可「整批确认写入」；最多5条、同一账号同一对话，在一个Serializable事务中执行。任何草稿过期、权限撤销、源样品/客户变化都会使整批不写入。提交后才发送实时通知，重复确认不重复记账。
- 模型/照片识别也可通过专用登记工具生成草稿；「调整录入」先取消原草稿，回到可编辑核对表，再生成新草稿，不允许改动已保存的待确认payload。真实供应商的识别准确性仍需联调，不能把模糊数字猜成金额。
- 预存款登记或涉及预存款的金额/状态/付款客户变更仍须在原页面选择会员、核对台账，快捷录入不直接扣款或冲正。历史、锁定、已完成样品不能直接修改。
- 助手每次打开会刷新启用状态，并有「刷新授权」入口，避免后台已保存启用但旧界面仍显示未启用。Mock模式只预览表格，不向模型发送演示数据，也不生成或确认真实草稿。

## 历史会话

- 顶部「历史会话」按最近活动排序，每页20条；仅列出当前操作者在当前数据账号下的聊天。主/子账号不能看到彼此的聊天，管理员也不能查看其他身份的聊天。
- 「新对话」只清空当前界面，不删除服务端历史。「查看并继续聊天」加载最新60条消息、原录入位置和草稿，支持分批加载更早消息；续聊仍使用原会话ID，可切换到当前已授权模型。每次请求只向模型发送最近24条文本历史，较早消息可回看但不假装无限记忆；旧照片不会自动重新发送，需要时重新上传。
- 读取前后重验当前身份、账号范围、配置版本和访问密码授权。权限/配置变化或访问授权失效时隐藏旧标题和内容，不携带旧敏感上下文继续请求。恢复相同有效访问授权后可重新加载；配置版本已改变的旧会话不可继续，需新对话。过期草稿展示为已过期，不会因恢复历史而复活。
- 删除需独立确认。服务端仅允许操作者删除自己的空闲会话，物理删除聊天及关联草稿，并使关联飞书旧卡片失效；不能删除正在回复或确认的会话。已确认业务数据及独立操作审计保留，删除聊天不是业务撤销。照片附件独立按原24小时期限清理。

### 子账号与后台写入边界

前台子账号、后台子管理员没有独立AI策略时一律关闭，不继承`*`默认策略。取消独立授权后恢复关闭；已有独立策略不会被自动扩展。

主管理员和单独授权的子管理员可登记已授权数据账号的付款客户、样品金额、费用状态；不允许后台修改检测原始输入、公式或参数。字段开放只增加可配置选项，不自动给任何账号勾选新增字段。后台若要为缺失客户新建客户，还需单独授权「客户资料 / 姓名名称」写入，不开放联系人等其他字段写入。

子管理员还需在独立AI策略选择「AI可访问的前台账号」，同时保留原后台账号范围。每项规则的`ownerIds`存于现有`AiPolicy.rules` JSON，空或缺失表示该菜单不允许访问任何数据账号；实际执行同时校验原后台授权、该菜单账号范围和字段许可。该扩展不需要数据库结构迁移。主账号会话每次只操作用户明确选定的一个账号。

## 启用

1. 服务端运行环境使用 Node.js 22.12 或更新版本（AI SDK 7 为 ESM）。
2. 配置原有 PostgreSQL `DATABASE_URL`，以及至少 32 字节、独立保管的 `AI_API_KEY_SECRET`。加密密钥不可随意更换，否则现存 API 密钥需重新保存。
3. 审核并应用 AI 迁移，包含 `20261009000000_add_ai_assistant`、飞书表迁移及本次 `20261011120000_ai_conversation_entry_context`，随后重新生成 Prisma 客户端并构建服务端。本次迁移只给 AI 会话增加可空的菜单上下文列，不改历史样品、财务或预充值记录。生产应用前仍需数据库备份和迁移核查；本次开发不自动发布生产。
4. 用真实主管理员登录，添加显示名称、供应商模型标识、HTTPS API 前缀和密钥。接口示例为 `https://api.example.com/v1`，不是网页地址，也不是完整 `/chat/completions` 路由。
5. 只勾选供应商实际支持的图片识别、工具调用能力，测试连接，再启用服务。
6. 配置默认或指定账号权限。默认不授予任何业务读写权限。菜单树可按前台/后台切换，默认收起二级菜单，支持展开/收起全部、全选读取、全选写入、清空、一级菜单批量授权、二级菜单单独授权、搜索及「字段与限制」细分。搜索会展开匹配结果。全选仅影响当前菜单侧及搜索结果；每个写入字段自动包含对应读取。只读和原流程操作不会因全选而开放。
7. 「全局禁止字段」是所有账号和模型共用的禁止名单，优先于账号授权。禁止某项后，该信息在其他菜单中的同义字段及已声明依赖的汇总字段也被阻止；例如禁止客户电话后，预充值菜单不能再返回电话，禁止支出金额后，财务报表不再返回支出及结余。

本地默认 Mock 登录仅显示界面预览，不保存模拟 AI 设置、不向模型发送演示数据。连接真实 API 时需要设置前台 `VITE_USE_MOCKS=false`、后台 `VITE_ADMIN_USE_MOCKS=false`。

## 菜单范围与支持的业务

权限目录覆盖当前前台全部 9 个一级菜单、25 个导航入口，以及后台全部导航入口，共 39 个业务数据集。同一菜单有多种数据时，在「字段与限制」中分开配置。导航入口全部列出不代表所有按钮和所有数据库字段都允许 AI 操作；未开放的操作会标记限制并继续使用原页面。

| 菜单 | 读取 | 写入 |
| --- | --- | --- |
| 数据计算、标样计算、系数计算 | 样品输入和检测结果、标样输入、系数页标准/测量原始行 | 前台当天既有样品登记与原始输入、标样输入、既有标准/测量行输入；后台仅付款客户、金额、费用状态。不改内部公式及参数 |
| 化验报告 | 图片及短信模板业务文字 | 修改模板文字，保留已有印章；不读取或写入印章文件 |
| 员工考勤 | 员工基础资料、每日排班、考勤、请假和类型、提成和类型、奖金、工资及调整 | 对应新增/修改、每日排班保存、请假通过/驳回、工资草稿生成和调整；不处理私密证件、照片、工资锁定/重开 |
| 预充值客户 | 本账号充值、充值剩余、本人消费及本人参与的结算 | 充值录入和主账号充值冲正；共享余额、对方充值、转账和双方确认不开放 |
| 财务/后台财务报表 | 支出、收入、未结款、月结账单/每日明细/客户备注、删除申请 | 前台新增支出、未结样品标记已结、月结状态更新、支出删除申请；后台提醒、月结客户备注及删除申请驳回 |
| 报表 | 样品/财务统计 | 派生统计只读，修改需在来源菜单完成 |
| 药品库存 | 库存、入库、出库及常用名称 | 新增入库/出库/常用名称；库存由原业务自动记账，不能直接覆盖库存数 |
| 客户总览 | 客户基本资料及本账号业务统计 | 新增客户；同名不覆盖，统计只读 |
| 黑名单 | 本账号上传的信息 | 新增/补充本人记录，保留已有图片，不读取其他账号记录 |
| 后台待办/异常/账号管理/AI API 配置 | 安全的申请摘要、异常记录、所选账号基本状态及模型公开信息 | 后台异常备注；历史样品审批、删除批准、账号与 AI 权限配置仍由人操作 |

后台助手可以多选 1 至 20 个已有授权的前台账号。服务端逐个验证所选账号，子管理员不能加入未分配账号；一个账号失效就拒绝整次查询，不把部分账号结果伪装成合计。多账号模式仅开放读取、统计和分页，明细带所属账号标识，统计同时返回分账号结果及合计；每页合计仍最多 50 条，不是每个账号各返回 50 条。更改账号选择会新建对话，历史、分页标记和权限指纹绑定完整账号集合。全局模型目录不按账号重复汇总。

同一笔双方转账结算在合并明细和顶层合计中按记录 ID 去重，参与账号标识只展示已选账号；分账号统计保留各自参与记录，因此不能相加冒充去重合计。查询结束、历史读取和模型回复返回前均重新校验完整账号集合；模型调用中途撤销任何账号授权，也不能继续显示旧回复。

后台仅选择一个账号时才开放有明确授权的写入能力，包括原备注、提醒、驳回，以及本次付款客户、样品金额、费用状态三个登记字段。检测原始输入、员工、公式及账本不向后台开放。多选时模型没有任何写入工具，草稿创建与确认接口也在服务端拒绝，快捷录入入口禁用；历史会话仍按完整账号集合隔离。前台主/子账号不因后台多选而得到跨账号权限。历史、锁定、完成样品沿用原审批流程。

后台助手必须选择已有授权的前台账号。在原备注、提醒、驳回能力之外，只有显式授权的三个样品登记字段及客户姓名新增可以替所选账号操作；后台不能修改员工、检测输入或直接改账本。历史、已锁定、已完成样品沿用原修改申请流程。转账确认、工资锁定/重开、历史样品审批、账号安全设置及批准删除保持人工原流程。数据库没有直接交给模型；模型只调用封闭业务工具，不能选择任意表、执行 SQL 或直接连接数据库。

## 源码与公式的边界

页面列出四类不可关闭的固定禁止项：源码/服务器文件、内部公式/系数/参数快照、密码/API 密钥/权限设置、越权的其他账号数据。无需再逐账号配置禁用开关；它们不存在于模型工具或输出白名单中。标样和系数页的授权只针对公开业务原始输入，不提供计算实现或内部参数。

**这限制的是 AI 通道，不是网站整体的源码保密。** 当前项目的 `src/utils/formulaEngine.ts`、标样/系数计算及相关前端逻辑仍在浏览器运行。浏览器接收的 JavaScript 和参数不能靠 AI 权限开关保密。若要求网站使用者也无法获取公式，需要另行将私有计算和参数迁到服务端，移除前端公式实现及敏感参数下发；这不属于本次菜单权限扩展。模型也可能自行猜测或编造公式，不能把模型回复当作内部实现证明。

## 权限与写入保障

- 会话和附件绑定登录操作者；前台归属按服务端 `dataOwnerId` 解析，后台账号范围按现有管理员授权解析。模型不能自选账号。
- 业务菜单权限、访问密码授权、AI 字段许可和全局禁止字段共同生效。内部源码、参数快照、计算公式、密钥、密码始终不在工具目录或输出中。
- 所有数据库读取经过明确字段投影；禁止字段也不参与关键词搜索，避免通过搜索结果旁路推断。
- 模型只能创建待确认草稿；确认入口不接受自定义值，只接受草稿 ID 和用户决定。卡片显示账号、菜单/日期/样品位置、字段、原值和拟写入值。
- 草稿 15 分钟后过期。确认时重新校验账号、字段权限、配置版本和目标数据版本。确认与原业务写入、原业务审计及 AI 审计在同一 Serializable 事务内完成；嵌套业务事务加入此事务，实时通知提交后发送；失败整批回滚，重复确认不重复写入。
- 改模型、禁用账号、更新菜单权限、改变访问密码授权或 AI 配置后，相关旧会话不能继续读取或执行草稿。
- 模型请求仅访问已配置 HTTPS 公网接口，阻止内网/云元数据、跨域、重定向及 DNS 重绑定。密钥只在服务端解密，不返回到浏览器。
- 照片只接受 JPG/PNG/WebP，核查文件头，每张最多 5MB、每次最多 3 张。照片保存在非公开数据库表，绑定操作者且24小时过期。过期照片在该账号下次上传时清除，不作为永久凭证保存。
- 每账号每日对话次数受限。聊天不发送访问授权 token、源码、服务端错误、工具栈或内部参数给模型。AI 路由也剥离原业务冲突响应中的完整草稿/快照，避免错误响应绕过字段授权。模型的自然语言可能出错，原始数据、百分数、单位和照片内容必须人工核对。
- 允许字段的业务数据和用户上传照片会发送给所选供应商；应按业务要求选择可信接口。改变模型会使用当前已授权会话文本。

## 完整统计与明细分页

- `summarize_business` 在服务器的只读一致性快照中扫描完整授权范围，返回记录数和已授权金额/数量合计，不向模型发送全部明细。金额使用十进制计算，以保留两位小数的字符串返回。`complete=true` 才表示本次范围统计完整；统计失败不返回部分合计。
- `query_business` 每页返回最多 50 条，先完成访问授权和公开字段关键词过滤，再分页。返回准确的 `totalRecords`、`hasMore`、`nextCursor`；`truncated` 与 `hasMore` 一致，恰好 50 条且无后续记录时不会误报截断。关键词不会搜索禁止字段、内部 ID 或样品位置文字。
- 在同一对话中说“下一页”或“继续查看”，模型应调用 `continue_business_query`，由服务器读取该对话最近一次查询的续查标记。也可指定业务菜单继续该菜单的查询，不要求用户复制标记。标记绑定操作者、数据账号、对话、菜单、日期、关键词、有效权限和业务数据版本，15 分钟过期。数据或权限变化后拒绝续查，需重新查询第一页，以免重复或遗漏。
- 可以指定开始/结束日期，单次最多 366 天。未指定范围时沿用原菜单口径：数据计算按当天，考勤/财务/流水按当月，客户/库存等无日期菜单按本账号全部记录。工资和月结账单按整月返回，工具会注明实际范围；无日期菜单不接受伪装成日期范围的查询。
- 样品 `totalRecords` 是授权可见的样品行数，可能包含空白预留行；`sampleCounts.detected` 是有原始检测输入的样品数，仅完整授权原始检测字段时返回；`priced` 是有有效价格的样品数。收入报表的 `totals.sampleCount` 沿用既有有效价格口径，收入包括实付充值、不会重复计入预存款消费。不能混淆这些口径，也不能从未授权字段推算被禁止的指标。
- 普通明细金额合计是当前范围的字段之和，不自动排除草稿、冲正或失效记录，不能当作净收入、结清金额或当前余额。工具的 `notes` 会明确口径，`validValues` 会说明有效值数量；缺失值不能当作已确认的零。收入等业务指标优先使用原业务报表的统计。
- 完整统计仍受账号范围、菜单/字段授权、全局禁止和原访问密码规则限制。受保护但未解锁的已完成样品不参与明细或统计；历史范围需要对应授权。查询完成后再次检查账号/权限/飞书绑定，过期或撤销时不返回旧结果。
- 为避免大范围查询拖垮服务，一次最多扫描 100,000 条源记录，查询快照最多 20 秒。超出时明确要求缩小范围，不把部分扫描伪称完整统计。这些服务保护限制与每页 50 条、每日对话次数上限分别独立。

## 审计与后续扩展

后台记录业务读取字段、草稿生成/确认/取消、写入位置和变更、模型连接测试、设置与账号权限变更。日志不存 API 密钥原文，不开放给模型。新增业务操作需先加入明确的菜单/字段目录、校验、确认卡片和事务执行器，再开放权限；不提供任意 SQL、文件系统或 shell 工具。

正式发布前需要配置真实模型并完成实际照片识别、工具调用兼容性验收。当前 UI 选择和配置实现不等同于供应商保证支持相应模型能力。
