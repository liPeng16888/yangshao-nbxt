# 未结款样品批量确认已结款设计

## 目标

在前端“财务 → 未结款”页面保留现有单条结款能力，并增加安全、可审计的批量确认功能。用户可以勾选当前筛选结果中的多个样品，查看数量和合计金额，经二次确认后一次性将它们标记为“已结款”。

## 范围

- 表格最左侧增加 Element Plus 多选列，表头全选仅作用于当前筛选后显示的行。
- 页面操作区增加“批量确认已结款”按钮，并显示已选数量。
- 保留现有每行“已结款”复选框和“跳转”按钮。
- 新增前端批量 API、状态仓库操作，以及服务端批量结款接口。
- 每条样品继续写入 `paymentStatus` 变更日志，并同步当前已加载的数据计算表。
- 不改动月结款、预存款和管理后台催款流程。

## 页面交互

1. 用户通过表格左侧复选框选择样品；表头复选框可选择当前客户筛选结果。
2. “批量确认已结款”按钮在没有选择时禁用，有选择时显示数量，例如“批量确认已结款（3）”。
3. 点击按钮后弹出二次确认框，内容包含样品数量及合计金额。
4. 确认后，页面进入批量处理中状态，禁用单行和批量结款操作，避免重复提交。
5. 成功后从未结款列表移除相应行、清空选择，并显示成功提示。
6. 用户取消确认时不产生任何状态变化。
7. 更换客户筛选条件时清空勾选，避免筛选后误操作不可见记录。
8. 单行结款继续沿用现有二次确认交互。

## 前端结构

### 页面组件

`FinanceUnsettledPage.vue` 负责：

- 持有表格实例和选中行状态。
- 响应 `selection-change`，计算选中数量和合计金额。
- 在客户筛选条件变化时清空表格选择。
- 展示确认弹窗，并调用状态仓库的批量结款方法。
- 在成功后显示提示；失败交由统一请求错误处理，同时保留列表数据。

表格通过 `row-key="blockId"` 标识样品。批量选择列只选择当前渲染的 `filteredRows`，不跨筛选条件保留隐藏选择。

### 状态仓库

`financeBills` 状态仓库新增独立的批量处理中状态和 `settleRows(rows)` 方法：

- 调用批量 API，并接收所有已保存的样品块。
- 将返回的样品块同步到当前已加载的化验数据表。
- 仅在整批请求成功后，从 `unsettledRows` 移除全部对应记录。
- 通过 `finally` 恢复处理中状态。

单行 `settleRow` 保持原有行为，并与批量操作共享“是否正在结款”的禁用条件。

### API 层

新增批量请求：

```text
PUT /finance/unsettled-samples/paid
{ blockIds: string[] }
```

响应为已更新的样品块数组。正式环境调用服务端批量接口；本地模拟环境先校验全部样品均存在且仍为“未结款”，再逐条保存并返回结果。

## 服务端事务

控制器接收 `blockIds`，服务层执行以下步骤：

1. 去重并校验数组非空。
2. 在数据库事务中查询所有目标样品及所属表格。
3. 验证所有样品都存在、属于当前前端账号，并且当前费用状态为“未结款”。
4. 如果任一目标不满足条件，抛出明确错误并回滚整批操作。
5. 对每个样品把 `paymentStatus` 更新为“已结款”，使用其参数快照重新计算结果。
6. 为每个样品写入一条 `paymentStatus` 变更日志。
7. 返回全部更新后的样品块。

事务保证不会出现部分样品已结款、部分样品仍未处理的中间状态。现有单条接口保持兼容。

## 错误处理

- 空选择在页面和服务端两层拦截。
- 重复 `blockId` 在服务端去重，不重复更新或写日志。
- 样品不存在、越权或状态已变化时整批失败，页面不移除任何行。
- 请求失败后恢复按钮状态；用户可刷新列表后重新选择。
- 单行和批量请求互斥，避免同一条记录被并发处理。

## 测试

采用测试驱动方式覆盖：

- 页面：选择数量、合计金额、无选择禁用、确认内容、筛选变化清空选择。
- 状态仓库：成功后批量移除并同步数据表；失败时保留全部未结款行并恢复状态。
- API：正式环境发送批量请求；本地模拟环境校验全部目标后更新。
- 服务端：整批成功、去重、空数组、样品缺失、越权、状态变化和事务回滚。
- 回归：现有单条结款仍可正常使用。

## 验收标准

- 用户能勾选一条或多条未结款样品并批量确认。
- 表头全选只覆盖当前客户筛选结果。
- 确认框准确显示选中数量和合计金额。
- 成功后选中记录全部从未结款列表消失，并同步为“已结款”。
- 任一目标无效时整批不修改，不出现部分完成。
- 单条结款、客户筛选、刷新和跳转功能不受影响。
