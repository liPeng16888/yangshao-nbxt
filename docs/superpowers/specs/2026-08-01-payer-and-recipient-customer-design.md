# 付款客户与数据发送客户拆分设计

## 目标

将数据计算页每个样品原有的“客户”信息拆分为“付款客户”和“数据发送”两行。付款客户作为样品唯一的财务归属客户；数据发送仅用于数据计算页以及生成短信、报告时展示和选择，不参与任何财务或客户统计。

本次修改必须兼容已经保存的历史样品。历史记录原有客户直接视为付款客户，不批量复制、不清洗、不覆盖生产数据。

## 数据模型与兼容

- 保留现有 `customerId`、`customerIds`、`customers`、`customerText` 字段，语义调整为付款客户。
- 新增 `recipientCustomerId`、`recipientCustomerIds`、`recipientCustomers`、`recipientCustomerText` 字段，保存数据发送客户。
- 付款客户限制选择一个；数据发送允许选择多个已保存客户，也允许手动输入名称。
- 现有样品输入保存在 JSON 中，因此不修改 Prisma schema，也不执行数据库迁移。
- 历史记录原客户字段仍在原位置，升级后自然显示为付款客户；新增的数据发送行保持空白。
- 新增字段纳入前后端允许保存字段、字段级自动保存、草稿恢复、冲突检测、实时同步和修改记录。

## 数据计算页面

原客户区域调整为三段纵向布局：

1. 样品名称。
2. 付款客户。
3. 数据发送。

付款客户继续复用现有客户搜索、新增客户、完整信息展示、复制和删除选择能力，但最多只能选择一个客户。数据发送复用相同编辑器并保留多选能力。

两行客户编辑器需要支持长内容：

- 客户标签和手动输入文字允许自动换行。
- 使用 `overflow-wrap: anywhere` 避免电话号码、微信号或连续字符撑出边界。
- 客户区域使用最小高度而不是固定高度，内容增加时由样品格自动增高。
- 操作按钮保持固定宽度并靠右，不挤压或遮挡客户文字。
- 缩放表格时仍保持文字在客户格内部，不产生横向覆盖。

## 财务与统计口径

以下功能只读取原客户字段，即付款客户：

- 收入账单。
- 未结款。
- 月结款信息收录和每日客户明细。
- 预存款客户匹配及每日明细。
- 报表收入统计。
- 前后台客户总览。
- 后台财务报表中的客户筛选和客户展示。

`recipientCustomer*` 字段不得进入金额、样品数量、客户归属或客户筛选统计。付款客户为空时按现有“无信息”规则处理，不回退到数据发送客户。

## 短信、报告与批量填写

- 批量填写弹窗原“客户”字段明确为“付款客户”，写入现有 `customer*` 字段。
- 化验短信和化验报告优先使用数据发送客户；数据发送为空时回退到付款客户，以保证历史记录和未填写数据发送的新样品仍可正常生成。
- 数据发送客户只影响短信、报告和本页面显示，不改变样品的财务归属。

## 保存与错误处理

- 两类客户都走现有 `patchBlock`、字段级脏字段保存和 SSE 同步流程。
- 编辑器一次更新形成同一组字段变更，避免只保存名称而漏掉客户 ID 或完整快照。
- 保存失败时继续保留本地输入和草稿，不因新增客户字段而绕过现有重试机制。
- 双设备修改不同客户角色时按不同字段合并；修改同一角色的同一字段时沿用现有冲突处理。

## 测试

- 历史样品原客户升级后显示在付款客户行，财务归属不变。
- 付款客户只能选择一个，数据发送可以选择多个或手动输入。
- 修改数据发送后，未结款、月结款、收入账单、客户总览仍归属付款客户。
- 付款客户为空、数据发送有值时，财务客户显示“无信息”。
- 短信和报告优先显示数据发送客户；数据发送为空时回退付款客户。
- 批量填写客户只修改付款客户，不覆盖数据发送。
- 付款客户和数据发送的长名称、电话、微信信息可以换行并带动客户格增高。
- 新增字段可以自动保存、草稿恢复、实时同步并参与冲突检测。
- 前端类型检查、相关组件测试、财务服务测试和后端构建通过。

## 非目标

- 不拆分或重新分摊已有多客户历史样品的金额。
- 不批量迁移历史数据。
- 不新增独立客户档案表；两类客户仍复用当前账号的客户资料库。
- 不修改客户资料本身的新增、编辑或删除规则。
