# 历史样品修改申请与后台审批设计

## 背景与目标

前端历史日期样品目前在页面、状态仓库和服务端均为只读。该边界继续保留，但前端账号可以针对单个历史样品提交修改申请；经有权限的后台管理员整份审批通过后，修改内容在同一事务中写入样品并直接生效。

本功能覆盖来样单位／样品名称、付款客户、结款金额、化验元素、费用状态和原始检测输入。公式结果不能直接填写；原始检测输入获批后，服务端必须使用该样品原有的参数快照重新计算全部派生结果。

## 已确认的业务规则

- 仅历史日期样品使用申请审批；当天样品继续使用现有直接编辑和自动保存流程。
- 一份申请只对应一个样品，但可以同时修改多个允许字段；审批时整份同意或整份拒绝。
- 同一样品最多存在一条待审批申请。
- 申请人可以撤回待审批申请，撤回后可重新提交；旧申请标记为已撤回并永久保留。
- 申请原因必填；拒绝原因必填；同意时审批备注可选。
- 超级管理员可以审批所有申请；子管理员只能审批已授权前端账号的申请。
- 若申请影响已结或部分结的月结账单，审批通过时将受影响客户当月结款状态重置为未结款，并保存重置前快照。
- 后台数据统计继续严格只读。后台只能通过待办事项中的专用审批接口使历史样品发生变化。

## 范围

### 允许修改的逻辑字段

| 业务字段 | 样品输入字段 | 说明 |
| --- | --- | --- |
| 来样单位／样品名称 | `sampleNumber` | 对应数据计算表 B 列 |
| 付款客户 | `customerId`、`customerIds`、`customers`、`customerText` | 作为一个整体修改，由服务端规范化客户快照 |
| 结款金额 | `price` | 有限数值或空值 |
| 费用状态 | `paymentStatus` | 仅允许系统现有费用状态 |
| 化验元素 | `elementNote` | 保留现有文本语义 |
| 原始检测输入 | `ironRaw` 等现有检测输入字段 | 使用 `labDetectionInputFields` 作为唯一白名单来源 |

### 明确不允许修改

- 编号 `sequence`
- 完成状态 `completed`
- 数据发送客户字段
- 普通备注 `note`
- 表格参数和样品参数快照
- `results` 中的铁、硅、铝、铝硅比、合量、比重等公式结果
- 当天样品及未来日期样品

### 非范围

- 不开放后台数据统计的直接编辑能力。
- 不改变当天样品的自动保存、冲突处理和实时同步。
- 不允许逐字段审批，也不允许后台修改申请值后再批准。
- 不删除或改写既有申请、单元格历史、样品、财务和预存款历史记录。

## 总体架构

新增独立的“样品修改申请”领域，不复用财务删除申请的数据模型。它由以下边界清晰的组件组成：

1. 前端申请 API、状态仓库、申请弹窗和申请记录面板。
2. 后台待办事项中的样品修改申请面板。
3. 服务端独立的样品修改申请模块、前端控制器、后台控制器、DTO 和服务。
4. Prisma 申请模型、状态枚举、待审唯一约束，以及单元格历史的可选申请关联。
5. 审批事务内的样品更新、公式重算、单元格日志、月结重置和提醒写入。

现有财务删除申请继续使用原接口和服务。后台 `TodoPage` 只负责分类切换，两个待办类型分别放入独立组件，避免把两套业务继续堆叠在一个页面文件中。

## 数据模型

### 状态枚举

新增 `LabSampleChangeRequestStatus`：

- `PENDING`
- `APPROVED`
- `REJECTED`
- `WITHDRAWN`

状态转换只允许：

```text
新建 -> PENDING
PENDING -> APPROVED
PENDING -> REJECTED
PENDING -> WITHDRAWN
```

所有终态不可再次转换。

### 申请记录

新增 `LabSampleChangeRequest`，至少包含：

- `id`
- `frontendUserId`：历史表格所属前端账号
- `requestedById`：实际提交人
- `sheetId`、`blockId`、`date`、`blockIndex`
- `baseBlockUpdatedAt`：提交申请时样品版本
- `sourceSnapshot`：服务端生成的原输入、原结果和参数快照
- `requestedChanges`：服务端规范化后的白名单字段补丁
- `previewResults`：服务端按原参数快照计算的申请后结果
- `reason`
- `status`
- `reviewRemark`
- `reviewedById`、`reviewedAt`
- `withdrawnAt`
- `settlementEffects`：审批导致的月结状态重置前后快照
- `createdAt`、`updatedAt`

申请分别关联所属前端账号、实际申请人、审核人、表格和样品。删除用户、表格或样品时使用限制或保留策略，不能级联删除审计记录。

`CellChangeLog` 增加可空的 `changeRequestId`，使审批产生的单元格修改历史可以直接追溯到申请；既有日志保持空值，不需要回填。

### 待审唯一约束

Prisma 模型无法直接表达 PostgreSQL 部分唯一索引，因此迁移中增加数据库约束：

```sql
CREATE UNIQUE INDEX "LabSampleChangeRequest_one_pending_per_block"
ON "LabSampleChangeRequest" ("blockId")
WHERE "status" = 'PENDING';
```

服务层仍先检查并返回友好提示；数据库索引负责消除并发提交竞态。

常用查询索引覆盖：

- `(frontendUserId, status, createdAt)`
- `(status, createdAt)`
- `(sheetId, blockId)`
- `reviewedById`

## 前端申请流程

### 历史表格入口

历史表格继续以只读方式加载，不解除 `LabSheet.readonly`，不启用单元格自动保存和实时同步。历史日期加载完成后，同时读取该日期的申请摘要并按 `blockId` 建立映射。

仅有可见业务数据的样品显示申请操作：

- 无待审申请：在样品名称区域显示“申请修改”。
- 有待审申请：显示“待审批”标签，以及“查看申请”“撤回申请”。
- 已同意、已拒绝或已撤回：表格展示当前真实数据，并允许再次申请。

### 申请弹窗

弹窗使用样品当前值的独立副本，不直接写入 `labSheetStore`。它包括：

1. 日期、样品编号和当前样品摘要。
2. 样品名称、付款客户、金额、化验元素、费用状态和原始检测输入编辑区。
3. 仅显示实际变化字段的“原值 -> 新值”对比区。
4. 原始检测输入变化后的公式结果预览，并标注“预览结果，以后台审批生效结果为准”。
5. 必填的修改原因。

付款客户继续复用当前客户选择语义，但弹窗只提交客户标识和自由文本；客户详细快照由服务端重新生成。公式预览复用现有前端计算函数，最终结果只信任服务端计算。

没有实际差异、原因为空、字段格式错误或正在提交时，提交按钮禁用。网络失败保留弹窗全部内容，用户可以重试。

### 提交后的状态

提交成功只更新申请状态，不修改历史样品。对应样品立即显示“待审批”。前端和服务端同时阻止重复待审申请。

页面增加“修改申请记录”入口，展示当前账号全部申请的日期、样品、变更摘要、原因、状态、审批原因和时间。待审申请可在二次确认后撤回；撤回操作只更新状态，不删除记录。

审批同意或拒绝后创建前端提醒。审批同意后，用户刷新或重新进入历史日期即可读取已生效数据和重新计算结果。

## 后台审批流程

### 待办事项页面

后台待办事项增加两个分类：

- 样品修改申请
- 删除申请

样品修改申请支持按状态、前端账号和日期筛选。列表显示申请时间、账号名称、样品名称、修改字段数量、申请原因和状态。

详情展示：

- 表格日期、样品编号和样品名称
- 每个字段的原值和申请值
- 修改前后公式结果对比
- 申请原因
- 月结状态可能受到的影响提示
- 申请、撤回和审批信息

审批人不能修改申请内容，只能整份同意或拒绝。同意前二次确认；拒绝必须填写原因；同意备注可选。终态申请不再显示审批按钮。

### 后台只读边界

后台数据统计页面继续只调用 GET 查询接口，不增加输入控件、直接保存按钮或通用样品写接口。审批写操作仅存在于以下专用端点：

- `POST /admin/lab-sheet-change-requests/:id/approve`
- `POST /admin/lab-sheet-change-requests/:id/reject`

超级管理员可操作全部前端账号。子管理员必须通过 `AdminAccessService` 校验目标申请所属前端账号，不能只依赖列表过滤或按钮隐藏。

## API 设计

### 前端账号接口

```text
POST /lab-sheets/change-requests
GET  /lab-sheets/change-requests
GET  /lab-sheets/change-requests/:id
POST /lab-sheets/change-requests/:id/withdraw
```

提交请求包含 `blockId`、`baseUpdatedAt`、白名单修改补丁和 `reason`。客户端携带当前访问授权头；服务端按现有访问组合规则验证历史日期与已完成样品敏感数据权限，不能通过已知 `blockId` 绕过访问保护。

列表和详情仅返回当前前端账号可见的申请。撤回接口只允许实际申请人或所属前端账号撤回自己的待审申请。

### 后台接口

```text
GET  /admin/lab-sheet-change-requests
GET  /admin/lab-sheet-change-requests/:id
POST /admin/lab-sheet-change-requests/:id/approve
POST /admin/lab-sheet-change-requests/:id/reject
```

列表支持状态、前端账号和日期过滤，按申请时间倒序。所有读取和写入均经过角色与前端账号授权校验。

### 输入验证

服务端不信任客户端提交的旧值、客户快照、预览结果或参数。创建申请时必须重新读取表格和样品，并验证：

- 样品归属当前前端账号。
- `sheet.date` 早于当前北京时间业务日期。
- 样品包含可见业务数据。
- 修改字段均在固定白名单中。
- 数值为有限数值或允许的空值。
- 费用状态属于现有枚举值。
- 付款客户属于当前账号；服务端重新生成客户快照。
- 修改前后存在至少一个实际差异。
- 不存在同一样品的其他待审申请。

字符串沿用现有字段规则；申请原因去除首尾空白后必须非空，并设置合理长度上限。任何 `results`、参数快照、完成状态或其他非白名单字段都会被拒绝，而不是静默忽略。

## 审批事务与直接生效

同意申请使用单一数据库事务：

1. 锁定申请记录和目标表格／样品。
2. 校验申请仍为 `PENDING`。
3. 校验审批人角色及前端账号授权。
4. 比较 `baseBlockUpdatedAt` 和原始快照，确认样品未在申请后发生变化。
5. 重新验证已规范化修改补丁。
6. 将补丁合并到当前输入。
7. 使用样品当前保存的 `parameterSnapshot` 调用服务端 `calculateResults`。
8. 更新样品输入和公式结果。
9. 为每个实际变化的底层输入字段写入 `CellChangeLog`，关联本次申请，并沿用现有异常记录计数规则。
10. 处理受影响的月结状态。
11. 将申请标记为 `APPROVED`，记录审核人、备注、时间和月结影响快照。
12. 在同一事务中创建前端提醒。

任一步失败则全部回滚。批准按钮重复点击、并发审批或审批已撤回申请都会得到明确的状态冲突响应，不重复执行写入。

拒绝操作锁定申请并验证状态，将其改为 `REJECTED`，保存必填拒绝原因和审核人，并在同一事务中创建前端提醒。

撤回操作锁定申请并验证所有权和状态，将其改为 `WITHDRAWN` 并记录时间。撤回、拒绝和同意后的记录均不可删除或再次转换。

## 月结状态一致性

收入、未结款、预存款、报表和客户总览直接读取样品输入，审批生效后的下一次查询会自然反映新值。

月结账单另外保存客户当月结款状态。审批修改 `price`、付款客户或 `paymentStatus` 时，服务端计算修改前后的“月份 + 前端账号 + 客户”影响集合。若集合中的月结记录当前为已结或部分结：

1. 将状态重置为未结款。
2. 将已结金额清空。
3. 将备注更新为“因历史样品修改审批，需按新汇总重新核对”。
4. 把原状态、原已结金额和原备注保存在申请的 `settlementEffects` 中。
5. 在审批详情和前端提醒中列出被重置的客户与月份。

已为未结款或不存在的记录不需要额外创建或重置。新汇总金额继续由样品数据实时计算。

## 冲突与错误处理

- **重复待审申请**：返回 409，并返回已有申请摘要供前端跳转查看。
- **样品版本冲突**：审批返回 409，不修改任何数据；后台提示申请人撤回后按最新数据重提。
- **越权**：返回 403，列表和详情均不得泄露未授权账号数据。
- **样品或申请不存在**：返回 404。
- **非法字段或格式**：返回 400，并指出问题字段。
- **申请已处理**：返回 409，不重复同意、拒绝或撤回。
- **网络失败**：前端保留申请草稿，不乐观创建重复记录。
- **事务失败**：样品、公式结果、单元格日志、月结状态、申请状态和提醒均保持原状。

## Mock 模式

Mock 模式实现与正式 API 相同的状态转换和主要校验：

- 历史日期限制和字段白名单
- 一个样品一条待审申请
- 申请、撤回、同意、拒绝
- 使用样品参数快照重新计算结果
- 月结状态重置
- 前端提醒与申请记录
- 超级管理员／授权子管理员的可见范围

Mock 数据不能成为正式 DTO 和业务规则的替代品；服务端测试必须独立覆盖真实校验和事务行为。

## 测试策略

实施采用任务级 TDD，每个任务遵循“失败测试 -> 最小实现 -> 回归验证”。

### 前端测试

- 只有历史日期显示申请入口；当天编辑和自动保存行为不变。
- 历史表格仍不能直接编辑或自动保存。
- 仅有业务数据的样品出现入口。
- 弹窗只编辑允许字段，并正确生成原值／新值差异。
- 原始检测值变化时公式预览正确。
- 无实际变化、原因为空和格式错误时不能提交。
- 待审状态阻止重复申请。
- 待审申请可撤回，终态申请不可撤回。
- 请求失败保留表单内容。
- 正式 API 和 Mock 行为一致。

### 后台测试

- 待办页面正确区分样品修改申请和删除申请。
- 状态、账号和日期筛选正确。
- 详情展示字段差异、公式结果差异和月结影响。
- 拒绝原因必填；同意备注可选。
- 超级管理员可审批全部账号。
- 子管理员只能审批已授权账号。
- 已撤回和已处理申请没有审批按钮。
- 数据统计页面继续无输入控件和样品写请求。

### 服务端测试

- 历史日期、样品归属、访问授权和可见业务数据校验。
- 字段白名单、数值、费用状态、客户归属和客户快照规范化。
- 一个样品只允许一条待审申请，包括并发创建。
- 撤回、拒绝和同意的合法及非法状态转换。
- 超级管理员和授权子管理员的审批权限。
- 样品版本冲突时整次回滚。
- 使用原参数快照重算全部公式结果，拒绝直接覆盖结果。
- 每个实际变化字段写入单元格历史并关联申请。
- 月结状态重置、原状态留档及无关记录不受影响。
- 样品、结果、日志、月结、申请和提醒的事务原子性。
- 重复点击与并发审批只生效一次。

### 端到端验收

1. 前端打开历史日期，为一个样品同时修改名称、付款客户、金额、化验元素、费用状态和原始检测值。
2. 提交后样品保持原值并显示待审批。
3. 授权子管理员能看到完整差异并同意申请。
4. 审批后重新读取历史日期，新值立即生效，公式结果按原参数快照更新。
5. 收入、未结款、月结、预存款、报表和客户总览反映新数据。
6. 受影响的已结或部分结月结记录变为未结款，并可从申请详情追溯旧状态。
7. 前端收到审批通知；后台申请详情和单元格历史可追溯操作人、原因、时间及变化。
8. 撤回、拒绝、越权、重复申请和数据冲突均不修改样品。

## 迁移与发布约束

迁移只新增申请枚举、申请表、索引、外键和 `CellChangeLog.changeRequestId` 可空字段：

- 不回填既有样品和单元格日志。
- 不删除或修改现有样品、财务、月结和预存款数据。
- 上线前必须审查生成的 SQL，确认没有表重建、危险默认值或无关迁移。
- 正式发布沿用可恢复备份流程，并在发布前后对历史样品数量、金额汇总、月结记录和预存款关键数据做快照比较。
- 迁移完成但功能代码尚未切换时，新增表和可空字段不影响旧版本运行。

## 验收标准

- 历史样品保持只读，仅通过申请弹窗提出修改。
- 一份申请对应一个样品，可包含多个字段，且同一样品只有一条待审申请。
- 申请可以撤回重提；所有状态记录永久可追溯。
- 后台管理员只能整份同意或拒绝，不能直接编辑历史数据。
