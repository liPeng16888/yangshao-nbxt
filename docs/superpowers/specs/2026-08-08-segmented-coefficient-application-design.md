# 系数按起始样品分段应用设计

## 目标

在前端“数据计算 > 系数计算”页面中，点击“应用系数”后先选择当天数据计算表中的起始样品。当前页面录入的空白值和系数从所选样品（含）开始应用，并立即重新计算该样品及后续已有样品；所选样品之前的数据、结果和参数快照保持不变。

后续再次选择更靠后的样品应用另一组参数时，形成新的参数分段。例如先从 003 应用参数 A，再从 008 应用参数 B，最终 003～007 使用参数 A，008 及以后使用参数 B。

## 术语与范围

- “样品编号”指数据计算表左侧按顺序显示的 `001、002、003……`，对应样品块的 `index`，不是用户填写的“样品编号”文本字段。
- “空白和系数”指完整的九项 `LabParameter`：铁空白、铁系数、硅空白、硅系数、铝系数 1、铝系数 2、钙系数、镁系数和钛系数。
- 操作仅作用于当前北京时间业务日的可编辑数据表，不允许修改历史只读表。
- 起始样品必须是当天数据表中已经存在的样品块；对话框不接受任意文本编号。
- 本次不新增参数历史表。每个样品已有的 `parameterSnapshot` 继续作为该样品实际使用参数的历史记录。

## 交互设计

点击“应用系数”后打开“选择应用起始样品”对话框：

1. 对话框列出当天已有样品，显示为 `001、002、003……`。
2. 用户必须选择一个起始样品，未选择时不能确认。
3. 确认区域明确提示：“将从样品 003（含）开始应用新的空白和系数，并重新计算 003 及后续已有样品；001～002 保持不变。”
4. 确认按钮文案为“确认应用”，取消不产生任何修改。
5. 应用期间按钮和对话框确认操作进入加载状态，阻止重复提交。
6. 成功后关闭对话框并提示“已从样品 003 开始应用新参数”；失败时保留页面输入并提示失败，不显示成功状态。

打开对话框前，前端先加载当天数据表。提交前先保存当前数据计算页尚未落库的自动保存内容；若存在无法保存或冲突的数据，停止应用并保留当前页面状态，避免使用旧输入重新计算。

## 数据与计算规则

一次应用操作同时完成以下规则：

1. 将当天表格的 `parameters` 更新为当前系数计算页面中的完整空白和系数，供后续新增样品和尚未录入检测数据的后续样品使用。
2. 对当天所有 `index >= startIndex` 的已有样品：
   - 将 `parameterSnapshot` 覆盖为本次新参数；
   - 使用样品现有 `inputs` 和新参数重新执行服务端公式计算；
   - 将新结果保存到 `results`。
3. 对 `index < startIndex` 的样品不修改 `parameterSnapshot`、`results` 或 `inputs`。
4. 无论后续样品当前是否填写检测数据，都更新其参数快照。空白样品的结果仍为空或零值，但以后首次录入检测数据时继续使用本次快照。
5. 再次从某个起始样品应用参数时，覆盖该起始样品及其后全部样品的旧快照和结果，因此新的分段边界以最后一次操作为准。
6. 新增样品继续使用当天表格当前的 `parameters`，也就是最后一次成功应用的参数。

示例：

| 样品范围 | 第一次从 003 应用 A 后 | 第二次从 008 应用 B 后 |
| --- | --- | --- |
| 001～002 | 原参数 | 原参数 |
| 003～007 | 参数 A | 参数 A |
| 008 及以后 | 参数 A | 参数 B |

## 后端设计

新增专用接口 `PUT /lab-sheets/parameters/current/apply`，请求体包含：

```ts
interface ApplyLabParametersPayload {
  parameters: LabParameter
  startIndex: number
}
```

保留现有 `PUT /lab-sheets/parameters/current` 行为，避免改变其他调用方。新接口负责校验当前用户、当前业务日、完整有限数值参数、正整数起始编号以及起始样品确实存在。

服务端在一个数据库事务中：

1. 读取当前表和按 `index` 排序的样品块；
2. 更新表格当前参数并写入 `savedAt`；
3. 逐个更新 `index >= startIndex` 的样品参数快照和按现有公式引擎得到的结果；
4. 返回完整的最新 `LabSheet`。

任一更新失败时事务整体回滚，不能出现表格参数已经改变但部分样品仍使用旧快照的状态。事务提交后发布一次 `sheet-reloaded` 实时事件，使同账号其他页面或设备得到同一份完整表格，而不是为每个样品发布多条事件。

## 前端状态设计

API 层新增分段应用方法；Pinia store 新增 `applyParametersFromIndex(parameters, startIndex)`：

- 先调用已有的全量待保存机制，失败或冲突时直接返回失败结果；
- 调用新接口并以返回的完整表格替换 `sheet`；
- 重置与新表格冲突的本地保存状态；
- 保持现有实时连接；
- 只在服务端成功后显示成功提示。

系数计算页从 store 的 `sampleBlocks` 生成可选编号，不在页面内复制样品数据。页面本地保存的标样和参数输入逻辑保持不变。

## 错误处理

- 当天没有样品块：不打开可提交的选择流程，并提示“当天暂无可应用的样品”。
- 起始编号不存在、不是正整数或已不在最新表格中：服务端拒绝请求，前端刷新当天数据后提示重新选择。
- 历史表或非当前业务日：服务端拒绝修改。
- 参数包含非有限数值：服务端拒绝整个请求。
- 待保存样品存在冲突或保存失败：不发送应用请求。
- 数据库事务失败：参数与样品全部保持操作前状态。

## 测试设计

### 服务端

1. 从 003 应用参数 A 后，001～002 快照和结果不变，003 及以后快照更新并按 A 重算。
2. 再从 008 应用参数 B 后，003～007 保留 A，008 及以后改为 B。
3. 起始范围内的空白样品也获得新快照，后续新增样品使用表格最新参数。
4. 请求在事务中同时更新表格参数和样品；失败时不留下部分更新。
5. 起始样品不存在、编号非法、参数非法和历史表修改均被拒绝。
6. 成功后只发布一次 `sheet-reloaded` 事件，并返回完整最新表格。

### 前端

1. 点击按钮先加载当天表格，再显示已有样品编号选择框。
2. 未选择起始样品不能提交；选择 003 时显示包含范围和重算影响的确认文案。
3. 提交前保存待处理的样品修改；保存失败或冲突时不调用应用接口。
4. 成功响应替换 store 中的完整表格，并显示正确起始编号的成功提示。
5. 取消、接口失败和重复点击不会修改本地表格或错误显示成功。
6. 原有参数保存、样品自动保存、实时同步和公式测试继续通过。

## 验收标准

- “应用系数”必须先选择当天已有的起始样品。
- 所选样品及其后的已有样品立即采用新空白和系数重新计算，之前样品完全不变。
- 多次从不同编号应用后，各样品的参数快照符合最后一次覆盖其范围的操作。
- 新增样品使用最后一次成功应用的参数。
- 操作具备原子性，失败不会产生部分应用。
- 同账号其他页面收到一次完整表格刷新。
- 相关自动化测试、前端构建、后台构建和服务端构建全部通过，本地浏览器完成 003 与 008 两次应用的实际验证且控制台无错误。
