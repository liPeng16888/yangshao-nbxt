# 样品复样记录设计

## 1. 目标

在“数据计算”中为原始样品增加可重复创建的复样记录。用户从工具栏选择一个或多个样品编号后，每个样品在原始计算区与“样品金额”行之间新增一条空白复样计算带；复样使用创建当时最新的参数快照和原计算公式，供用户单独录入、保存和对照原始数据。

后台管理端同步提供复样数据查看能力，但严格只读。复样只承担检测数据与计算结果的留存，不产生第二笔样品费用，也不进入财务、预付款、客户统计、短信或报告等既有业务统计。

本功能同时支持电脑端和手机端，允许同一原始样品存在多组复样，并保证并发创建、自动保存、历史完成数据权限和作废留痕安全。

## 2. 已确认的产品规则

1. 数据计算工具栏在“标记样品完成”左侧增加“样品复样”。
2. 点击后弹出与“标记样品完成”相似的编号选择弹窗，可一次选择多个原始样品。
3. 每个被选样品新增一组空白复样；同一原始样品允许存在多组复样，按“复样1、复样2……”编号。
4. 电脑端复样计算带位于原始检测/计算区与“样品金额”行之间，不复制样品名称、客户、金额等资料行。
5. 复样继承原始样品的样品名称、付款客户、化验元素、样品金额和付款关系，只单独保存检测输入与计算结果。
6. 每组复样创建时读取工作表最新参数并固化参数快照；此后参数修改不追溯改变该复样的计算依据。
7. 复样与原始样品使用同一套服务端计算公式，但复样输入、结果和保存版本互相独立。
8. 原始样品完成后仍允许新增复样；原始样品继续保持完成和加密状态，不因复样而退回可编辑状态。
9. 空白复样允许删除；只要任一检测输入曾填写，便不能物理删除，只能作废并保留记录。
10. 作废复样只读显示，后台也可查看；不允许恢复或继续修改。
11. 不自动计算或展示原始与复样、复样与复样之间的差值，也不增加合格/不合格阈值。
12. 手机端同步支持创建、编辑、查看、删除空白复样和作废已填写复样。
13. 后台管理端只读查看有效和已作废复样，不提供任何新增、编辑、删除、作废或恢复入口。

## 3. 领域边界

复样是 `SampleBlock` 的从属检测记录，不是新的原始样品，也不是第二个收费项目。

### 3.1 复样包含

- 原始样品关联。
- 在该原始样品内稳定递增的复样序号。
- 检测输入 `inputs`。
- 服务端计算结果 `results`。
- 创建时最新工作表参数 `parameterSnapshot`。
- 有效或作废状态、作废原因和操作审计。
- 创建、更新和作废时间，以及实际操作账号。

### 3.2 复样不包含

- 独立样品编号、样品名称或付款客户。
- 独立样品金额、结算状态或预付款扣减。
- 独立化验元素选择。
- 独立短信、报告、客户样品数量或财务流水。
- 自动差值、偏差百分比或合格判定。

所有需要展示的样品资料从父 `SampleBlock` 读取。这样可避免复样数据被既有按 `sampleBlocks` 聚合的收费和报表流程误计入。

## 4. 数据模型

### 4.1 独立复样表

采用已确认的第一种方案：新增独立 `SampleRetest` 模型，而不是把复样数组继续塞进 `SampleBlock` JSON。

Prisma 模型采用以下结构：

```prisma
enum SampleRetestStatus {
  ACTIVE
  VOID
}

model SampleRetest {
  id                String             @id @default(uuid())
  sampleBlockId     String
  sequence          Int
  inputs            Json
  results           Json
  parameterSnapshot Json
  everFilled        Boolean            @default(false)
  status            SampleRetestStatus @default(ACTIVE)
  voidReason        String?
  createdById       String
  updatedById       String
  voidedById        String?
  createdAt         DateTime           @default(now())
  updatedAt         DateTime           @updatedAt
  voidedAt          DateTime?

  sampleBlock SampleBlock @relation(fields: [sampleBlockId], references: [id], onDelete: Cascade)

  @@unique([sampleBlockId, sequence])
  @@index([sampleBlockId, status, sequence])
}
```

`SampleBlock` 增加 `retests SampleRetest[]` 关系。实际操作账号字段沿用现有审计 ID 模式；数据归属不从请求体接收，而是始终经 `SampleBlock -> LabSheet -> frontendUserId` 校验。

### 4.2 空白与已填写定义

- 初始“空白复样”定义为所有允许录入的检测输入都为空，且 `everFilled=false`。
- `0` 是有效检测输入，不属于空值。
- 计算结果、参数快照、序号、时间和状态等系统字段不影响空白判断。
- 任一有效检测输入首次持久化时，服务端在同一事务中把 `everFilled` 单向置为 `true`；即使后来把输入清空，也不能改回 `false`。
- 服务端删除时同时要求 `everFilled=false` 且当前持久化输入为空，不能信任客户端传入的“空白”标志。这样保证“曾经录入过数据”的复样只能作废，不能物理删除。

### 4.3 序号与并发

- 序号只在同一 `sampleBlockId` 内递增，作废或删除后不回收旧序号。
- 创建时在事务内读取当前最大序号并插入下一序号。
- `@@unique([sampleBlockId, sequence])` 是最终并发保护；并发冲突时服务端在有界次数内重试分配。
- 一次批量选择中的全部复样在同一事务内创建：任一父样品不存在、越权或不可写时整批失败，不留下部分记录。
- 创建和保存沿用现有化验数据的持久化幂等请求模式：请求记录保存幂等键、请求指纹、目标工作表/复样、操作类型与响应快照；同键同指纹返回原响应，同键不同指纹拒绝。网络重试不会多建复样或重复应用保存。

### 4.4 迁移边界

数据库迁移只新增枚举、表、外键和索引，不修改任何历史 `LabSheet`、`SampleBlock`、财务、预付款或客户数据。上线前必须备份数据库并审查迁移 SQL，不运行与本功能无关的迁移。

## 5. 参数快照与计算

1. 创建复样时由服务端重新读取该 `LabSheet.parameters`，规范化后写入 `parameterSnapshot`。
2. 批量创建时同一工作表内所有新复样使用同一事务读取到的最新参数版本。
3. 后续编辑工作表参数只影响此后新建的复样；既有复样继续使用自己的快照。
4. 保存检测输入时，服务端用 `parameterSnapshot` 调用现有 `calculateResults` 计算并覆盖 `results`。
5. 客户端可即时计算用于交互反馈，但提交的结果不作为可信持久化依据。
6. 输入规范化、精度、空值处理和原始样品保持一致，避免同一输入在两处得到不同结果。
7. 作废记录不再计算；任何更新请求均返回 409 或 422，并保留原记录。

## 6. 客户端 API 与写权限

### 6.1 接口

- `POST /lab-sheets/:sheetId/sample-retests`
  - 请求：`{ sampleBlockIds: string[] }`
  - 响应：按所选样品返回创建后的复样 DTO。
- `PUT /lab-sheets/:sheetId/sample-retests/:retestId`
  - 请求：变更后的检测输入、`baseUpdatedAt`、变更字段或等价的乐观并发信息。
  - 响应：服务端规范化输入、重新计算的结果和新 `updatedAt`。
- `DELETE /lab-sheets/:sheetId/sample-retests/:retestId`
  - 仅允许删除仍为空白的有效复样。
- `PATCH /lab-sheets/:sheetId/sample-retests/:retestId/void`
  - 请求：可选作废原因和 `baseUpdatedAt`。
  - 仅允许将已填写的有效复样单向改为 `VOID`。

常规 `GET /lab-sheets/:date` 在每个 `sampleBlock` 下返回按序号排序的 `retests`，使电脑端和手机端使用同一数据契约。Mock API 必须与真实 API 保持字段、状态码、权限和错误行为一致。

### 6.2 身份和授权

- 前端主账号可管理自己的复样。
- 只有拥有 `DATA_MAIN` 权限的前端子账号可管理主账号数据中的复样。
- 服务端始终使用认证身份的 `dataOwnerId` 限定工作表和父样品，禁止跨租户访问。
- 复样创建、保存、删除和作废只允许在当前可编辑日期执行；沿用现有“当天表可写，历史表只读”的规则。
- 例外只针对父样品状态：当天工作表中的原始样品即使已完成，仍可新增和编辑其有效复样，父样品本身保持完成。
- 实际操作人用登录账号 ID 审计，数据所有者仍是主账号。

### 6.3 完成数据访问保护

- 父样品完成后，原始检测数据和全部复样受同一“查看加密数据”授权保护。
- 未取得该完成数据授权时，客户 API 对复样输入、结果和参数快照采用与父样品一致的脱敏策略，不能通过复样接口绕过保护。
- 获得授权后才可查看或在当天允许范围内编辑有效复样。
- SSE 事件不得携带可绕过授权的完整敏感内容；客户端收到事件后按当前授权重新查询。

## 7. 自动保存、冲突与实时同步

1. 每条复样拥有独立草稿和保存状态，不复用父 `SampleBlock.updatedAt`。
2. 保存携带 `baseUpdatedAt` 和实际变更字段；服务端发现版本过期时返回 409，不静默覆盖。
3. 不同复样可并行保存；同一复样的连续输入按现有自动保存队列串行化。
4. 409 时保留本地输入，提示数据已被其他账号修改，并提供加载服务器最新值后重试的路径。
5. 创建成功后向同租户同日期频道发送复样变更事件；其他窗口更新该样品的复样列表。
6. 删除或作废事件同步移除可编辑行或将其切换为只读状态。
7. 重试创建请求需要客户端请求标识或服务端等价幂等机制，避免网络成功但响应丢失后重复创建。
8. 切换日期、退出页面或组件卸载时，旧请求不得覆盖新页面状态；尚未保存的本地草稿按账号、数据所有者、日期、样品和复样 ID 隔离。

## 8. 电脑端交互

### 8.1 工具栏与选择弹窗

- “样品复样”按钮放在“标记样品完成”左侧，按钮顺序与用户标注一致。
- 弹窗复用完成选择弹窗的视觉和选择模式，但标题、说明与提交文案明确为创建复样。
- 每行显示样品编号、样品名称、原始样品完成状态和现有复样数量。
- 已完成样品仍可选择；不属于当天或无写权限时整项禁用并说明原因。
- 提交期间锁定重复操作；批量创建失败时保持选择，显示服务端错误，不插入半成品 UI。

### 8.2 表格中的复样计算带

- 每条复样插在对应原始样品检测/计算行之后、“样品金额”行之前。
- 左侧显示“复样1、复样2……”及有效/作废状态；不复制样品名称、付款客户、数据发送、样品金额、费用、化验元素和备注行。
- 复用原表的元素列宽。每个检测单元格采用上方输入、下方结果的紧凑纵向布局，使一组复样占用一条计算带。
- 只渲染父样品已选择的化验元素；未选择元素保持不可编辑的空白样式。
- 行尾提供参数快照时间/查看入口、保存状态，以及“删除”或“作废”操作。
- 新建成功后自动滚动到第一条新复样并聚焦第一个可输入字段。
- 作废复样灰色只读显示，保留输入、结果、参数快照和作废信息。
- 不显示差值、偏差百分比或合格状态。

## 9. 手机端交互

- 数据计算顶部操作区同步提供“样品复样”，选择弹窗使用手机全屏或底部安全区友好的现有模式。
- 每个样品卡片增加“复样记录（n）”折叠区，`n` 包含有效和作废记录。
- 展开后按序号显示复样卡片，字段顺序与原始检测项一致；输入与结果上下排列。
- 有效复样可编辑并自动保存；空白复样显示“删除”，已填写复样显示“作废”。
- 作废记录灰色只读，显示作废时间和原因；不提供恢复入口。
- 新建后自动展开对应样品和第一条新复样，避免用户寻找新增位置。
- 手机和电脑端读取、保存完全相同的 DTO 与规则，不建立移动端专属数据结构。

## 10. 后台严格只读查看

### 10.1 页面

在后台数据统计/化验数据表中，每个原始样品增加“查看复样（n）”展开入口。展开区按“原始、复样1、复样2……”展示：

- 检测输入和计算结果。
- 复样参数快照及创建时间。
- 有效或已作废状态。
- 创建、更新、作废时间和允许展示的操作人信息。
- 作废原因。

后台不显示差值，也不允许编辑任一字段。

### 10.2 只读边界

- 后台通过既有数据统计 GET 响应在每个原始样品下内嵌复样，避免增加独立加载状态和额外请求。
- 不新增任何 `/admin` 复样 POST、PUT、PATCH 或 DELETE 路由。
- 后台 Vue 组件不得出现输入框、保存、删除、作废、恢复或可触发写请求的控件。
- 后台主管理员和受限后台子账号继续按现有客户授权范围查询，服务端必须校验其可见租户。
- “后台只读”同时由 UI、HTTP 方法、控制器、授权和业务服务边界保证，不能只靠隐藏按钮。

## 11. 既有业务隔离

复样不改变以下既有业务结果：

- 样品金额与未结算金额。
- 收入、支出、月结和财务图表。
- 预付款余额、扣减、共享预付款和结算流水。
- 客户样品数量、客户总览和排行榜。
- 化验短信、化验报告和报告汇总。
- 原始样品完成数量、完成时间和发送状态。
- 原始样品的样品名称、客户、元素、备注和价格。

实现时这些模块不得改为遍历复样；新增回归测试应明确证明创建、填写、删除或作废复样前后上述结果相同。

## 12. 错误处理

- 批量创建任一父样品无效、跨租户或不可写：整批拒绝并指出原因。
- 空白复样删除前弹出确认；服务端若发现已被其他窗口填写，返回冲突并保留记录。
- 已填写复样作废前弹出确认，可选填写原因；作废成功后不可撤销。
- 作废记录保存：拒绝并刷新最新状态。
- 参数快照缺失或格式无效：拒绝保存并记录服务端错误，不回退到当前参数偷偷重算。
- 乐观并发冲突：不覆盖本地值，提示加载最新数据。
- 网络中断：保留本地草稿和重试入口，不重复创建复样。
- 实时事件到达时若本地有未保存内容：提示远端更新，不自动覆盖。

## 13. TDD 与验收

实施遵循逐项 RED → 最小 GREEN，按数据模型、服务端领域规则、客户 API、电脑端、手机端、后台只读和业务隔离分阶段提交。

### 13.1 服务端与数据库

- 迁移只新增复样模型、关系、枚举和索引，历史关键数据不变。
- 单样品和批量创建、最新参数快照、稳定序号及并发唯一性。
- 批量事务全成全败和创建幂等。
- 复样计算与现有 `calculateResults` 的同输入同参数结果一致。
- 客户端伪造结果不能写入数据库。
- 空值、`0` 和各检测字段正确区分；从未填写的空白可删，曾经填写后即使清空也只能作废。
- 作废单向、只读和审计留痕。
- `baseUpdatedAt` 冲突不静默覆盖。
- 主账号、拥有 `DATA_MAIN` 的子账号可写；无权限子账号 403。
- 数据所有者隔离、跨租户 ID 拒绝。
- 当天可写、历史只读；当天已完成父样品仍可新增复样。
- 完成数据授权同时保护原始和复样。
- Mock 与真实 DTO、状态码和权限一致。

### 13.2 业务隔离

为财务、预付款、客户总览、报表、短信和化验报告分别增加回归断言，证明多组有效/作废复样均不会增加样品数、金额、流水或输出项目。

### 13.3 客户端

- 电脑端按钮准确位于“标记样品完成”左侧。
- 选择 001 后复样行准确位于原始计算区和“样品金额”之间。
- 001 可连续创建复样1、复样2，分别输入和保存，互不覆盖。
- 参数在两次创建之间改变时，两条复样保留各自创建时快照。
- 空白删除、填写后作废、作废只读；不显示差值。
- 自动保存、网络重试、409 冲突和实时同步不丢数据。
- 完成样品在未授权时复样脱敏，授权后按规则显示。
- 手机端可完成创建、展开、编辑、删除空白和作废已填写的完整流程。
- 电脑与手机切换不会产生重复或不同契约的数据。

### 13.4 后台

- 有效和作废复样均可展开查看，顺序与客户侧一致。
- 页面没有编辑控件，也不会发出非 GET 请求。
- `/admin` 不存在复样写路由；直接尝试写请求返回 404/405 或授权拒绝。
- 后台子账号只能查看获授权客户，不能借复样查询越权。

1. 运行复样相关定向测试、完整 Vitest、前端/后台/服务端构建和 Prisma 校验。
2. 排除 `.worktrees/**`、`.pnpm-store/**` 和 `.superpowers/**`，避免把隔离目录测试误计入结果。
3. 在电脑端浏览器实际验证按钮位置、复样计算带、两组数据独立保存和完成数据权限。
4. 在手机视口实际验证创建、编辑、删除/作废和折叠展示。
5. 在后台浏览器验证只读展开，并通过网络/API 检查确认只有 GET。
6. 对迁移前后的历史样品、财务和预付款关键数据做数量与金额快照对比。
7. 所有验证通过后再按备份优先流程发布 VPS；发布后独立检查前端、后台、API、复样持久化和关键历史数据。

## 14. 非目标

本次不实现：

- 原始与复样差值或偏差百分比。
- 合格阈值、自动判定或告警。
- 复样费用、独立付款或预付款扣减。
- 复样专属短信、报告或客户统计。
- 作废恢复、序号复用或复样迁移到其他样品。
- 批量复制原始检测值到复样。
