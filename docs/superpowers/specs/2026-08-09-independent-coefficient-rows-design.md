# 系数计算两表独立增删设计

## 目标

将“数据计算 > 系数计算”页面中的“标样含量”和“标样系数计算”改为两套完全独立的样品列表。每张表都能单独新增、进入选择模式并批量删除样品；任一表的增删操作不得改变另一张表的行数、内容或编号。

删除后，系统按展示顺序补齐自动编号。例如删除自动编号 `003` 后，原自动编号 `004` 变为 `003`。用户手动修改过的特殊编号保持不变。

## 范围

- 本次仅修改系数计算页面的本地标样含量行和系数计算行。
- 两张表的数据继续按当前登录用户保存在浏览器 `localStorage`，不新增服务端表或接口。
- “应用系数”仍使用页面中的九项空白和系数，并应用到当天数据计算表；其既有分段应用规则不变。
- 本次不改变公式算法、标样计算页面或当天数据计算样品块的增删逻辑。

## 数据边界

### 标样含量

“标样含量”只管理 `standardRows`，包含编号以及铝、硅、铁、钙、镁、钛含量。它拥有独立的新增数量、增加操作、删除选择状态和选中行集合。

### 标样系数计算

“标样系数计算”只管理 `calculationRows`，包含元素编号、六项实测输入和计算结果。它拥有另一套独立的新增数量、增加操作、删除选择状态和选中行集合。

### 独立性规则

1. 向 `standardRows` 增加或删除行时，不读写 `calculationRows`。
2. 向 `calculationRows` 增加或删除行时，不读写 `standardRows`。
3. 页面初始化不再按标样含量行数补齐系数计算行。
4. 两张表分别至少保留一行。
5. 两张表的选择模式互不影响，可以分别进入或退出；执行某张表的删除后，只清空该表的选择状态。

## 编号规则

每行增加持久化的 `autoCode` 标记：

- 新增行的 `autoCode` 为 `true`，编号按该表新增后的顺序生成三位数字。
- 用户编辑编号输入框后，该行的 `autoCode` 变为 `false`，以后删除其他行时保留该编号原值。
- 删除后按剩余行的展示顺序遍历：`autoCode: true` 的行改为新的三位顺序编号，`autoCode: false` 的行保持不变。
- 两张表各自独立重编号。

例如，表中依次为自动编号 `001`、自定义编号 `A-02`、自动编号 `003`、自动编号 `004`。删除第三行后，剩余行显示为 `001`、`A-02`、`003`。

旧数据没有 `autoCode` 时按以下规则迁移：若编号等于该行载入时的位置编号，例如第 3 行为 `003`，则识别为自动编号；其他编号识别为自定义编号。迁移只补充标记，不清除任何已有输入。

## 新增交互

两张表底部分别显示自己的新增控件：

- 数量范围继续为 1～50，默认 1。
- “标样含量”的确认按钮只向 `standardRows` 添加行。
- “标样系数计算”的确认按钮只向 `calculationRows` 添加行。
- 新增行为空白行，编号从该表当前行数之后继续生成。
- 两个新增数量分别持久化。读取旧版共用 `addCount` 时，用它初始化两个新数量；以后只保存新的独立字段。

## 删除交互

每张表底部在新增控件旁提供“删除样品”按钮。

1. 点击后，仅当前表进入删除选择模式，表格第一列出现行复选框，表头提供全选。
2. 操作区显示已选数量，以及“取消”和“确认删除”。
3. 未选择任何行时不能确认删除。
4. 允许一次选择多行。若选择数量等于或超过当前表行数，则不能确认，并显示“至少保留一个样品”。
5. 点击“确认删除”后弹出二次确认，内容列出所选行当前显示编号和总数量。
6. 用户取消二次确认时不修改数据，并保留当前选择，便于重新核对。
7. 用户确认后，删除所选行、按编号规则重排剩余行、退出当前表的选择模式并清空选择。
8. 删除结果由现有深度监听立即写入当前用户的本地存储。

删除按钮和确认弹窗采用 Element Plus 既有交互样式。按钮文案和提示明确区分“标样含量”与“标样系数计算”，避免误删另一张表。

## 状态与持久化

本地存储结构新增：

```ts
interface CoefficientCalculationStorage {
  parameters?: Partial<LabParameter>
  standardAddCount?: number
  calculationAddCount?: number
  standardRows?: StoredStandardContentRow[]
  calculationRows?: StoredCalculationRow[]
}

interface StoredRowIdentity {
  id?: string
  code?: string
  autoCode?: boolean
}
```

旧字段 `addCount` 仅用于兼容读取，不再写入。删除模式和选中行集合属于临时界面状态，不写入 `localStorage`，刷新页面后默认退出删除模式。

保存继续使用现有的用户隔离键 `ys_coefficient_calculation_inputs:<user>`。无需数据库迁移。

## 错误与边界处理

- 空选择：确认删除按钮禁用。
- 试图删除全部行：阻止操作并提示至少保留一个样品。
- 二次确认取消：不删除、不重编号。
- 本地旧数据损坏：继续沿用现有容错方式，使用默认三行；两张表分别恢复，不再互相补齐。
- 页面没有可用登录信息：继续使用 `guest` 存储键。
- 删除或新增不会触发 `applyParametersFromIndex`，也不会写入当天服务端样品数据。

## 测试设计

### 独立新增

1. 标样含量新增两行时，只有 `standardRows` 增加两行。
2. 标样系数计算新增一行时，只有 `calculationRows` 增加一行。
3. 刷新载入不同长度的两张表时，保持各自长度，不执行补齐。

### 独立删除

1. 标样含量多选删除后，系数计算行及输入完全不变。
2. 系数计算多选删除后，标样含量行及内容完全不变。
3. 未选择、选择全部、取消二次确认均不删除数据。
4. 成功删除后退出对应选择模式并清空选择。

### 编号与迁移

1. 删除自动编号 `003` 后，后续自动编号依次补位。
2. 自定义编号在前面或后面的行被删除时保持不变。
3. 新增行获得自动编号标记和正确的下一编号。
4. 旧存储数据正确推断自动编号或自定义编号，并把旧 `addCount` 迁移到两个独立数量。
5. 保存和重新载入后，`autoCode` 标记及两张表的独立长度保持不变。

### 回归验证

- 现有九项参数、本地输入、公式结果和“应用系数”分段应用测试继续通过。
- 前端实际源码测试、后端测试和三个生产构建目标通过。
- 在内置浏览器分别验证两张表独立新增和删除；不确认任何会改变当天服务端样品数据的“应用系数”操作；控制台无错误。

## 验收标准

- 两张表各自拥有独立的增加和批量删除功能。
- 任一表增删后，另一张表的行数、数据和编号完全不变。
- 每张表始终至少保留一行。
- 删除后自动编号按顺序补齐，用户自定义编号保持原值。
- 删除操作包含表内多选、全选状态、已选数量和明确的二次确认。
- 现有用户本地数据兼容迁移且不丢失。
- 刷新页面后两张表的独立状态正确恢复。
- 自动化测试、构建和内置浏览器检查全部通过。
