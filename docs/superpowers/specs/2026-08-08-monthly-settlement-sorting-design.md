# 月结款汇总表排序设计

## 目标

在前端“财务 > 月结款”页面的“月结款信息收录”汇总表中，为“金额”“样品数量”“结款状态”三列增加表头排序。排序只改变当前页面的行展示顺序，不修改月结款数据，也不向后端保存排序状态。

## 功能范围

- “金额”按数值从小到大或从大到小排序。
- “样品数量”按数值从少到多或从多到少排序。
- “结款状态”使用固定业务顺序排序：
  - 升序：已结款、部分结款、未结款。
  - 降序：未结款、部分结款、已结款。
- 任一时刻最多只有一列处于排序状态。用户选择另一列后，原排序列自动取消。
- 表头连续点击遵循升序、降序、取消排序的循环；取消后恢复表格收到的原始汇总行顺序。

以下内容不在本次修改范围内：

- “月结款每日客户明细”表格排序。
- 服务端接口、数据库结构和排序参数。
- 排序条件持久化或页面刷新后恢复。
- 月份筛选、客户筛选、导出范围和导出内容。

## 交互设计

“金额”“样品数量”“结款状态”表头显示可排序提示。点击某个表头后，表格展示当前排序方向；再次点击切换方向；第三次点击取消排序。

使用 Element Plus 表格原生单列排序行为管理表头状态。这样三列共享同一套交互，且切换列时只保留最新选择的排序列，不增加额外筛选控件。

## 实现设计

### 金额和样品数量

为金额列补充 `amount` 字段绑定并启用本地排序；为已有 `sampleCount` 字段的样品数量列启用本地排序。两个字段均按数值比较，避免按格式化后的金额字符串排序。

金额仍使用现有格式化函数显示人民币金额，显示格式与排序值彼此独立。

### 结款状态

为结款状态列绑定 `settlementStatus` 字段，并使用自定义比较函数。比较函数通过固定等级映射完成排序：

| 结款状态 | 升序等级 |
| --- | ---: |
| 已结款 | 0 |
| 部分结款 | 1 |
| 未结款 | 2 |

Element Plus 根据当前升序或降序方向应用比较结果，因此同一比较函数同时支持两个方向。

若运行时遇到未识别状态，该状态排在已知状态之后，避免异常数据导致排序失败；正常业务数据仍只使用上述三种状态。

### 数据流与编辑行为

排序仅由表格组件对 `report.summaryRows` 的当前展示副本执行。用户修改结款状态、结款金额或备注时，仍通过现有保存逻辑提交原行数据。排序不会改变行标识、编辑目标、汇总计算、筛选条件或导出数据源。

数据因月份切换、刷新或保存操作而重新加载时，表格继续使用当前组件支持的排序行为；不额外写入浏览器存储或服务端。

## 测试设计

页面组件测试覆盖以下内容：

1. 金额列和样品数量列使用数值字段并启用排序。
2. 结款状态列启用排序并使用自定义业务顺序。
3. 状态比较函数验证“已结款 < 部分结款 < 未结款”，反向排序由表格方向处理。
4. 三列使用表格原生单列排序配置，不启用多列联合排序。
5. 现有状态编辑、金额编辑、备注保存、月份筛选和导出测试继续通过。

完成组件测试后运行前端全量测试和生产构建，并在本地页面检查三列表头的升序、降序、取消排序及跨列切换。

## 验收标准

- 金额和样品数量可以分别按数值升序、降序并取消排序。
- 结款状态升序为“已结款、部分结款、未结款”，降序完全相反。
- 切换到另一列排序时，之前的排序列不再保持激活。
- 排序不修改任何月结款记录，不影响编辑、筛选和导出。
- 页面无控制台错误，相关自动化测试与生产构建全部通过。
