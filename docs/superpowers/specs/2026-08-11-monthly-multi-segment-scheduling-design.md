# 月度多时段排班与请假员工多选设计

日期：2026-08-11

## 目标

将员工考勤中的周排班模板替换为月度每日排班。每个工作日支持多组计划上班、下班时段，并在相邻工作时段之间自动计算休息时间。管理员可按月查看、编辑、批量覆盖和复制上月排班。

考勤记录同步支持管理员手工填写多组实际出勤时段。系统不接入考勤机、定位、员工自助账号或自动打卡；没有手工实际出勤记录时，默认员工按计划正常出勤。请假管理的员工筛选改为多选。

## 已确认业务规则

- 不支持跨日夜班。每个计划或实际时段必须在同一自然日内。
- 每天可增加多组“上班—下班”时段，时间必须严格递增且不得重叠。
- 相邻计划时段之间的空档自动显示为休息时间，不计入工作时长。
- 当日计划工作时长等于所有计划工作时段时长之和。
- 批量设置会完整覆盖所选日期的旧排班；覆盖前显示受影响日期数量并要求确认。
- 当月应出勤天数由存在有效工作时段的排班日期自动统计，不再手工填写。
- 月休额度继续由管理员按员工、月份设置。
- 没有手工实际出勤记录时，默认正常出勤，不自动判定迟到、早退或缺勤。
- 管理员录入实际出勤时段后，系统才逐段计算迟到、早退和缺勤。
- 真正缺勤必须由管理员手工登记；已批准请假按现有请假单位和时长覆盖排班工时。
- 加班时长继续手工填写，不根据实际出勤时段自动增加。
- 新月份支持复制上月排班，不提供“按星期批量设置”。
- 月历仍支持自由勾选任意多个日期后批量设置同一套班次。
- 请假列表员工筛选支持多选；空选显示全部员工；新增或编辑请假仍一次只选择一名员工。

## 数据模型

### 月度每日排班

新增每日排班实体，至少包含：

- 前台账号 ID
- 员工 ID
- 日期
- 工作日或休息日状态
- 当日计划总分钟数
- 备注
- 创建、更新时间

前台账号、员工和日期组成唯一业务约束。所有记录继续使用租户复合外键，拒绝跨账号访问。

### 计划工作时段

每日排班下包含零到多条有序计划时段：

- 每日排班 ID
- 顺序号
- 计划开始时间
- 计划结束时间

休息日不得包含计划时段。工作日必须至少包含一条有效时段。

### 实际出勤时段

现有每日考勤记录下增加零到多条有序实际出勤时段：

- 考勤记录 ID
- 顺序号
- 实际上班时间
- 实际下班时间

实际时段仍由管理员手工录入。不存在考勤记录或考勤记录没有实际时段时，不视为异常，而是按计划正常出勤。

### 月度设置

保留月休额度字段。现有应出勤天数字段不再作为管理员可编辑的工资输入；工资生成时从当月每日排班统计工作日数量，并把计算结果写入工资快照。

旧周排班数据暂时保留，用于新版上线后首次生成当前月排班。某员工某月一旦存在每日排班，此月只读取每日排班，不再回退到旧周模板。临时调班在兼容迁移时优先于旧周模板。

## 服务端接口与事务

前台增加以下能力：

- 查询指定员工、月份的每日排班和计划时段。
- 新增或更新单日排班。
- 批量覆盖多个明确日期的排班。
- 复制上月排班到目标月份。
- 查询和保存每日考勤的多组实际出勤时段。

批量覆盖和复制上月必须在单个数据库事务中执行。任意日期校验失败时整批回滚。所有写接口继续校验：

- `EMPLOYEE_ATTENDANCE` 有效访问授权。
- 当前登录前台账号与记录所有权。
- 员工归属。
- 目标月份是否已有已确认工资。
- 时间格式、顺序、重叠和同日限制。

后台接口继续只提供 GET 查询。后台月度排班页面展示每日排班、全部计划时段、休息时间和总工时，不提供保存、复制、批量覆盖或导出控件。

## 时间与考勤计算

计划总分钟数由服务端根据计划时段计算，忽略客户端传入的汇总值。

没有手工实际出勤时段时：

- 计划工作时段全部视为正常完成。
- 迟到、早退、缺勤均为零。
- 已批准请假仍按请假规则计入工资与月休额度。

存在手工实际出勤时段时：

- 按顺序将实际时段与计划时段配对。
- 实际开始晚于对应计划开始的分钟数计入迟到。
- 实际结束早于对应计划结束的分钟数计入早退。
- 未被实际出勤或已批准请假覆盖的计划分钟计入缺勤。
- 多余实际时段不会自动计入加班；加班分钟仍以管理员手工字段为准。
- 只有上班没有下班、时段交叉、重叠、跨日或无效时间禁止保存。

迟到和早退分钟以实际时段的服务端计算结果为准，不再接受独立手工修改。缺勤有两种来源：存在实际时段时由未覆盖的计划分钟自动计算；没有实际时段时默认为正常，只有管理员明确填写缺勤分钟才计为缺勤。已批准请假覆盖的分钟从缺勤中扣除。加班分钟始终保留为独立手工字段。

工资草稿和确认读取同一套月度每日排班。工资确认后保存的快照保持不可变；撤销确认后才允许修改对应月份的排班和考勤。

## 前端交互

### 月度排班页

采用月历卡片式布局：

- 顶部包含员工、月份、复制上月排班、批量选择和刷新。
- 工作日卡片显示所有计划时段、休息总时长和工作总时长。
- 休息日显示灰色状态；无记录日期显示“未排班”。
- 点击日期打开右侧抽屉，编辑工作日状态、计划时段和备注。
- 每增加一组时段即增加一组计划上班、计划下班控件。
- 抽屉实时显示各段休息时间和当日工作总时长，最终结果仍由服务端复算。

批量模式允许勾选任意多个日期。用户填写一套计划时段并应用时，页面显示选中日期数和将被覆盖的已有排班数；二次确认后完整覆盖。

“复制上月排班”按自然日期序号复制，例如上月 1 日复制到本月 1 日。目标月不存在的日期忽略；目标月多出的日期保持未排班。目标月已有任何排班时必须二次确认，确认后目标月排班由复制结果完整覆盖。

### 考勤记录页

- 将“打卡”文案统一改为“实际出勤”。
- 管理员可手工增加、删除多组实际上班和实际下班时间。
- 未填写时显示“默认正常出勤”。
- 迟到和早退改为只读计算结果；没有实际时段时允许管理员明确填写缺勤分钟；加班分钟继续手工填写。

### 请假管理页

- 页面顶部员工筛选改为可搜索多选框。
- 没有选中员工时显示全部员工的请假记录。
- 选中一个或多个员工时显示这些员工的合并结果。
- 日期、状态筛选继续与员工多选共同生效。
- 新增或编辑请假表单的员工字段仍是单选。

真实接口可接受多个员工 ID；Mock 与真实接口使用相同筛选语义，避免前端只在当前已加载结果上做不完整过滤。

## 错误处理

- 无效、重叠、倒序或跨日时段返回具体到日期和时段序号的错误。
- 批量覆盖和复制上月失败时保留用户已填写的班次表单，页面展示服务端错误。
- 已确认工资月份禁止写入，并提示先填写原因撤销工资确认。
- 新月份没有上月排班时，复制按钮提示“上月暂无可复制排班”，不创建空记录。
- 请假多选查询失败时保留已选员工和其他筛选条件，允许直接重试。

- 多计划时段的总工时与休息时间计算。

## 不在本次范围

- 自动打卡、员工自助打卡账号、定位、考勤机或第三方考勤硬件接入。
- 跨日夜班。
- 按星期批量设置。
- 根据实际出勤时间自动计算加班。
- 部署生产环境或执行生产数据库迁移。
