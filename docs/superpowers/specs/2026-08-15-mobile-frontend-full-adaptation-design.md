# 客户前端全功能手机版适配设计

日期：2026-08-15

## 目标

在保留现有电脑端客户前端界面和管理后台界面不变的前提下，将客户前端除已完成的“数据录入”外的全部功能优化为适合 iPhone 使用的手机版界面，并继续兼容后续 Android 手机。

本次改造必须满足：

- 手机端与电脑端使用相同账号、权限、业务规则、API 和数据库业务数据。
- 现有电脑端页面继续使用当前表格、侧栏和交互，不因手机版改造而降级。
- 手机端不通过压缩桌面表格实现，而是对复杂表格提供卡片、折叠区、抽屉和底部操作区。
- 手机端左上角抽屉负责切换一级菜单；屏幕底部只显示当前一级菜单的二级菜单。
- 底部二级菜单一屏固定显示最多三个，超出部分可横向滑动选择。
- 没有二级菜单的一级页面不显示底部导航栏。
- 已确认可正常使用的手机“数据录入”界面保持现有设计，只接受后续必要的共享导航和回归修正。
- 标样计算与系数计算的草稿由服务端按账号保存，实现电脑与手机跨设备同步。

## 范围边界

### 本次范围

- 客户前端手机版导航框架。
- 数据计算下的标样计算和系数计算手机版。
- 化验报告两个二级页面手机版。
- 员工考勤六个二级页面手机版。
- 财务五个二级页面手机版。
- 药品库存三个二级页面手机版。
- 报表、客户总览、黑名单三个单页模块手机版。
- 上述页面使用的客户选择器、筛选器、确认框、导出预览、访问验证等公共交互手机版。
- 标样和系数草稿的服务端存储、账号隔离、跨设备冲突与旧本地草稿迁移。

### 不在本次范围

- 管理后台手机版改造。
- 电脑端客户前端重新设计。
- 微信小程序、原生 iOS/Android App 或新的登录方式。
- 离线数据库和离线业务编辑。
- 推送通知。
- 生产发布和生产数据库迁移；完成代码与本地验收后另行授权。

## 方案选择

采用“共享业务逻辑和路由，复杂页面分别渲染桌面视图与手机视图”的方案。

没有选择纯 CSS 压缩桌面页面，因为系数、考勤、财务等页面含宽表格和密集操作，缩小字体或依赖横向表格滚动不能满足正常手机操作。没有另建独立手机应用，因为会复制路由、权限、计算规则和保存逻辑，长期容易产生电脑与手机行为差异。

具体原则：

- 页面入口、Store、API、公式、验证和权限保持共享。
- 使用现有 `useMobileLayout()` 作为唯一布局判断。
- 简单页面可以复用同一组件并使用响应式布局。
- 宽表格、密集编辑器和多步骤操作使用独立手机展示组件。
- 同一路由只挂载一套可编辑视图，禁止桌面表格与手机卡片同时挂载。
- 抽取共享逻辑是为了复用规则，不顺带重构无关业务。

## 导航设计

### 统一菜单来源

将客户前端一级菜单、二级菜单、路径和图标集中到一份导航配置中，电脑侧栏与手机壳共同读取，避免手机版再次遗漏桌面已有功能。

一级菜单及二级菜单映射如下：

- 数据计算
  - 数据录入：`/data`
  - 标样计算：`/data/standard-sample`
  - 系数计算：`/data/coefficient`
- 化验报告
  - 图片模板：`/lab-report/image-template`
  - 短信模板：`/lab-report/sms-template`
- 员工考勤
  - 排班考勤概览：`/employee-attendance/schedules`
  - 员工档案：`/employee-attendance/employees`
  - 考勤记录：`/employee-attendance/records`
  - 请假管理：`/employee-attendance/leave`
  - 提成与奖金：`/employee-attendance/compensation`
  - 工资统计：`/employee-attendance/payroll`
- 财务
  - 支出账单：`/finance/expenses`
  - 收入账单：`/finance/income`
  - 未结款：`/finance/unsettled`
  - 月结款：`/finance/monthly-settlement`
  - 预存款：`/finance/prepaid/add`
- 药品库存
  - 药品库存：`/medicine-inventory/stock`
  - 药品入库：`/medicine-inventory/inbound`
  - 药品出库：`/medicine-inventory/outbound`
- 报表：`/reports`
- 客户总览：`/customers-overview`
- 黑名单：`/blacklist`

预存款客户列表等同一业务内部的深层路由继续归属于“预存款”二级菜单，不额外占用底部栏。

### 一级菜单

- 左上角按钮打开全高抽屉。
- 抽屉只显示一级菜单、访问设置和退出登录。
- 点击一级菜单后进入该模块默认二级页面并关闭抽屉。
- 当前一级菜单保持高亮。

### 底部二级菜单

- 仅在当前一级菜单包含两个或更多二级菜单时显示。
- 一屏平均展示三个二级菜单；只有两个二级菜单时各占一半宽度。
- 四个及以上二级菜单使用横向滚动轨道和滚动吸附，不换行、不缩小文字。
- 当前二级菜单高亮，并在进入页面或路由变化后自动滚动到可见位置。
- 支持手指滑动，不依赖细小左右箭头。
- 每个菜单触控区域至少 44px，高度包含底部安全区域。
- 单页一级模块隐藏底部栏，页面内容直接使用底部安全区域。
- 页面自己的批量操作栏、保存栏和确认栏位于二级导航上方，不能相互遮挡。

## 手机版通用交互

### 页面骨架

- 顶部固定栏显示当前页面标题、一级菜单入口和在线状态。
- 页面主体使用动态视口高度和 iPhone 安全区域。
- 筛选条件默认收纳为紧凑摘要栏，点击后打开全宽抽屉或全屏面板。
- 主要操作按钮优先放在页面顶部操作区；进入批量或编辑模式后使用固定底部操作区。
- 所有可点击控件最小触控尺寸 44px。
- 数量、金额、检测读数等字段使用适合的手机数字键盘。

### 列表和表格

- 手机端不得依赖整个页面横向滚动。
- 每条桌面表格记录转换为摘要卡片，先显示识别信息、核心状态和关键金额。
- 次要字段通过“详情”折叠区或全屏详情查看。
- 排序、筛选、批量选择、增加、删除和导出功能继续保留。
- 只有确实需要横向比较的小型数据组允许在卡片内部局部滚动。

### 表单和对话框

- 简单表单使用单列或双列布局；窄屏回退单列。
- 长表单按业务分组折叠，默认只展开当前需要操作的一组。
- 桌面弹窗在手机端使用全屏对话框或底部抽屉。
- 保存失败时保留全部输入，不关闭对话框。
- 删除、更正、工资确认、批量覆盖等高风险操作继续二次确认。

### 加载与错误

- 首次加载显示骨架或明确加载状态。
- 列表加载失败保留筛选条件并提供重试。
- 保存状态区分等待、保存中、重试中、成功、失败和冲突。
- 网络中断不承诺离线业务提交；可恢复草稿在网络恢复后重试。

## 各模块设计

### 数据计算

#### 数据录入

保留当前已确认的样品卡片、分组折叠、自动保存、批量操作、报告分享和 PWA 行为。共享导航接入后进行回归，不重新设计录入卡片。

#### 标样计算

- 页面顶部提供“标样计算”说明和跳转系数计算的入口。
- 铝、硅、铁三个算法使用独立卡片。
- 卡片标题显示算法名称和关键结果摘要，内容可折叠。
- 输入项使用两列数字表单，结果使用颜色区分但同时保留文字标签。
- 每个算法保留现有重置功能。
- 输入后立即使用现有 `standardSampleCalculator` 计算，不复制公式。
- 草稿自动保存到服务端并显示同步状态。

#### 系数计算

- “标样含量”“标样系数计算”“九项参数”作为三个可折叠区域。
- 桌面宽表格在手机端转换为一张样品一张卡片。
- 标样含量卡显示编号及铝、硅、铁、钙、镁、钛含量。
- 系数计算卡显示编号、六项原始读数和对应结果。
- 保留增加样品、选择删除、全选、至少保留一项、自动编号和手工编号。
- 九项参数使用与数据录入一致的折叠参数面板。
- “应用到当天数据表”继续使用现有参数应用流程，起始样品选择器改为全屏抽屉。
- 公式继续调用共享公式引擎，不能建立手机专用计算逻辑。
- 参数、样品行和读数自动同步到服务端。

### 化验报告

- 底部二级菜单显示“图片模板”“短信模板”。
- 模板编辑区改为单列分组表单，固定文本、元素顺序和显示选项分别折叠。
- 图片预览使用适合屏幕宽度的缩放容器，不产生整页横向滚动。
- 生成图片继续优先调用系统分享；不支持时显示预览并提示长按保存。
- 短信模板支持实时预览、复制和恢复默认值。
- 现有模板内容、文件名和业务规则保持不变。

- 点击日期打开全屏日详情与排班编辑抽屉。

- 搜索、状态筛选放入顶部筛选抽屉。

- 月休额度和工资影响继续使用现有服务端规则。

#### 提成与奖金

- 员工与月份筛选保持固定摘要。
- 提成、奖金和说明按员工卡片编辑，金额使用数字键盘。
- 批量操作和保存状态放在底部操作区。

#### 工资统计

- 工资总览改为员工工资卡，显示应发、扣款、实发和确认状态。
- 工资组成在卡片详情中展开。
- 确认、撤销确认和导出继续执行现有锁定及快照规则。

### 财务

- 底部二级菜单显示支出、收入、未结款、月结款、预存款。

- 支出和收入记录使用账单卡片，新增及编辑使用全屏表单。

- 月结款显示客户月度汇总卡，账单明细在全屏面板中编辑和导出。
- 预存款显示账户余额卡、充值/扣减记录和客户列表入口。
- 金额精度、排序循环、账单生成、PNG 导出和财务权限保持不变。

### 药品库存

- 底部二级菜单显示库存、入库、出库。
- 当前库存使用药品卡片，显示名称、数量、单位和更新时间。
- 入库与出库表单默认折叠在页面顶部，提交后刷新记录卡片。
- 药品和日期筛选使用抽屉。
- 库存不足、单位锁定、数量精度和更正流水规则保持不变。
- 更正操作使用全屏原因表单并二次确认。

### 报表

- 作为单页一级模块，不显示底部导航栏。
- 汇总指标使用两列卡片，图表改单列并适配屏幕宽度。
- 时间与统计维度使用筛选抽屉。
- 图表提示、图例和空状态支持触摸操作。

### 客户总览

- 作为单页一级模块，不显示底部导航栏。
- 客户列表改为客户卡片，显示名称、联系方式、结款与样品摘要。
- 单选和多选客户筛选使用全屏选择器。
- 客户详情和相关记录在全屏面板中查看。

### 黑名单

- 作为单页一级模块，不显示底部导航栏。
- 黑名单记录使用卡片，突出姓名、电话、命中原因和状态。
- 查询、添加、编辑和导入使用手机表单或全屏抽屉。
- 批量导入结果提供成功、重复和失败的清晰汇总。
- 现有访问密码和命中提醒规则保持不变。

## 标样与系数跨设备同步

### 数据模型

新增 `FrontendCalculationDraft`，每条记录表示一个前台账号的一类计算草稿：

- `id`
- `frontendUserId`
- `kind`: `STANDARD_SAMPLE | COEFFICIENT`
- `payload`: JSON
- `revision`: 整数版本号
- `createdAt`
- `updatedAt`

唯一约束为 `frontendUserId + kind`。查询和写入始终从当前 JWT 获取账号范围，客户端不能指定其他账号。

标准样草稿保存铝、硅、铁输入。系数草稿保存九项参数、两类样品行、增加数量和自动编号状态。服务端对 JSON 结构、字段集合、行数、编号和有限数值执行 DTO 验证，不能接受任意 JSON。

### API

- `GET /calculation-drafts/:kind`：读取当前账号草稿；不存在时返回空草稿和版本 `0`。
- `PUT /calculation-drafts/:kind`：携带 `baseRevision` 和完整规范化草稿，成功后版本加一。
- 冲突返回 `409`，同时返回服务器最新版本摘要。
- 覆盖冲突必须由用户确认，再携带服务器最新版本执行一次明确覆盖。

### 数据流

1. 页面加载服务器草稿。
2. 服务器无草稿且本机存在旧 `localStorage` 数据时，只执行一次旧草稿导入。
3. 服务器已有数据时以服务器为准，不用旧本地数据静默覆盖。
4. 输入变化后更新当前页面状态并延迟自动保存。
5. 保存成功后更新本地缓存和版本。
6. 网络失败时保留本地缓存并显示重试状态。
7. 另一设备修改导致版本冲突时保留本机内容，提示加载服务器版本或确认覆盖。

本地存储仅作为当前账号的恢复缓存，读取和写入异常不得阻断服务器数据加载、计算或保存。
电脑端标样与系数页面也改为读取同一服务端草稿，但桌面布局和操作入口保持不变。

### 迁移安全

- Prisma 迁移只新增枚举、草稿表、索引和账号关系。
- 不修改或清空现有样品、参数、客户、财务、考勤、药品、黑名单和账号数据。
- 不运行 `db push --force-reset`、重置或 seed。
- 生产迁移前必须备份数据库并保留回滚版本。

## 组件与状态边界

- 导航配置只描述菜单和路由，不承载权限或业务状态。
- `AppMobileShell` 根据当前路由派生一级菜单和二级菜单，不为每个页面手写判断。
- 公共手机组件只负责展示和交互，不直接调用页面专属 API。
- 页面级 Store 或现有组合式逻辑继续负责加载、保存、冲突、筛选和权限。
- 桌面视图和手机视图通过一致的 props/事件或 Store 操作共享数据。
- 公式、金额、工资、库存、日期和权限规则保持在现有共享工具或服务端中。

## 分阶段实施

### 阶段 1：导航与公共手机组件

- 统一导航配置。
- 一级抽屉和可滑动二级底栏。
- 安全区域、页面底部占位和操作栏叠放规则。
- 通用筛选抽屉、记录卡片、全屏表单和加载/错误状态。

### 阶段 2：数据计算补齐

- 标样计算手机版。
- 系数计算手机版。
- 服务端草稿存储、旧本地草稿迁移和冲突处理。

### 阶段 3：化验报告

- 图片模板、短信模板和手机分享/保存回归。

### 阶段 4：药品、客户、黑名单和报表

- 先改造以查看和单记录操作为主的页面，稳定通用卡片与筛选模式。

### 阶段 5：财务

- 改造五个财务二级页面、批量结款、账单编辑和导出。

### 阶段 6：员工考勤

- 改造六个考勤二级页面、日历、编辑抽屉、工资确认和导出。

### 阶段 7：全量回归与实机验收

- 全部手机版路由逐项验收。
- 电脑端客户页面逐项对比。
- 管理后台回归确认无变化。
- iPhone 实机验证后再单独决定生产发布。

每个阶段严格执行失败测试、最小实现、重构、阶段验证和独立提交。前一阶段通过后再进入下一阶段，避免一次性修改全部页面后难以定位回归。

## 测试与验收

### 导航

- 电脑侧栏和手机抽屉读取同一导航映射，全部客户前端路由均有入口。
- 手机抽屉只显示一级菜单。
- 二级菜单为两个时平均显示，为三个时一屏完整显示，为四个以上时可滑动。
- 当前项自动进入可见区域并保持高亮。
- 单页模块隐藏底部栏。
- 底部业务操作栏不会遮挡二级菜单或页面内容。

### 页面

- 复杂可编辑页面在手机宽度只挂载手机编辑器、在桌面宽度只挂载桌面编辑器；简单共享页面不得同时挂载两套可编辑控件。
- 列表、筛选、增加、编辑、删除、更正、批量、导出和权限操作逐项覆盖。
- 页面主体不存在意外横向滚动。
- 所有控件满足 44px 触控区域，输入键盘类型正确。
- 加载、空状态、服务器错误、网络恢复和冲突状态可操作。

### 数据与服务端

- 标样和系数草稿按账号隔离。
- 电脑编辑后手机可读取，手机编辑后电脑可读取。
- 首次旧本地草稿只在服务器为空时导入。
- 非法 JSON、越权账号和无效数字被拒绝。
- 两台设备并发修改产生可恢复冲突，不静默丢失本机内容。
- 应用系数继续正确更新现有数据表及分段参数。

### 浏览器与实机尺寸

- 375×812。
- 390×844。
- 393×882。
- 430×932。
- 手机横屏。
- 桌面 1440×900。

iPhone 实机至少验证登录、一级菜单、滑动二级菜单、全部二级页面、数字键盘、全屏表单、自动保存、跨设备同步、图片分享、网络中断恢复和重新打开保持登录。

### 完整回归

- Vitest 排除 `.worktrees/**`、`.pnpm-store/**`、`.superpowers/**`。
- 客户前端与管理后台 `vue-tsc --noEmit`。
- 客户前端与管理后台 Vite 生产构建。
- NestJS 测试和生产构建。
- Prisma 格式化、校验、生成和迁移差异检查。
- 电脑端数据计算、化验报告、考勤、财务、药品、报表、客户和黑名单逐项确认无变化。

## 发布边界

- 本设计和后续实施均在隔离功能分支中完成。
- 本地完成不等于生产发布。
- 生产发布需单独授权，并执行数据库备份、迁移审查、构建、切换、API 验证、关键数据核对和回滚材料保留。
- 发布后必须验证账号登录、跨设备草稿、数据计算、实时刷新、报告、财务、考勤、药品和历史数据未受影响。
