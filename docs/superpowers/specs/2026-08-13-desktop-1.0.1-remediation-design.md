# 仰韶桌面软件 1.0.1 基础能力整改设计

## 1. 目标和范围

本次把已发现的 macOS 基础功能缺失一次性整改为桌面外壳 `1.0.1`，并解决报告模板、短信模板、来样单位快捷名称和常用化验元素组合只保存在单台电脑、主账号与子账号无法共享的问题。

整改同时适用于“仰韶化验内部系统”和“仰韶化验后端系统”的通用桌面能力；数据库配置同步只属于客户前台“仰韶化验内部系统”。后台桌面软件仍然只读使用现有后台网页，不新增模板管理入口。

本次包含：

1. 主账号与其全部前端子账号共用服务器中的业务模板和快捷配置。
2. 右键复制、粘贴、剪切、撤销、重做、删除和全选。
3. 启动、普通刷新和强制刷新时的明确加载状态、超时和重试。
4. 完整的 macOS/Windows 标准菜单、页面查找和缩放。
5. 桌面版本升级为 `1.0.1`，显示版本、构建时间和提交号并生成新安装包校验值。

本次不把化验表未保存草稿、临时系数计算过程、临时标样计算过程、窗口位置或界面偏好上传服务器；它们继续保存在当前电脑。也不修改既有化验业务记录、财务记录、账号权限或生产数据内容。

## 2. 共享边界与账号归属

以下四类配置改为服务器持久化：

| 配置 | 服务器分区键 | 前端权限 |
| --- | --- | --- |
| 化验报告模板（含电子公章） | `LAB_REPORT_TEMPLATE` | `LAB_REPORT_IMAGE_TEMPLATE` |
| 化验短信生成模板 | `LAB_REPORT_SMS_TEMPLATE` | `LAB_REPORT_SMS_TEMPLATE` |
| 来样单位快捷名称 | `LAB_REPORT_SAMPLE_UNITS` | `DATA_MAIN` 或 `LAB_REPORT_IMAGE_TEMPLATE` |
| 常用化验元素组合 | `LAB_ELEMENT_GROUPS` | `DATA_MAIN` |

所有配置归属于 `CurrentUser.dataOwnerId`：主账号登录时它等于主账号 ID；子账号登录时它等于所属主账号 ID。因此同一主账号下的主、子账号看到并编辑同一套配置，不同客户主账号之间严格隔离。

客户端请求中不接受 `dataOwnerId`、`frontendUserId` 或主账号 ID。服务端只能从已认证的 `CurrentUser` 解析数据所有者，并用 `CurrentUser.id` 记录实际修改人。子账号还必须通过对应的叶子菜单权限守卫；不能通过直接调用接口读取或修改未授权模板。

## 3. 数据模型

新增分区式偏好表，避免修改一个配置时覆盖另一个配置：

```prisma
enum FrontendPreferenceSection {
  LAB_REPORT_TEMPLATE
  LAB_REPORT_SMS_TEMPLATE
  LAB_REPORT_SAMPLE_UNITS
  LAB_ELEMENT_GROUPS
}

model FrontendBusinessPreference {
  id             String                    @id @default(uuid())
  frontendUserId String
  section        FrontendPreferenceSection
  value          Json
  version        Int                       @default(1)
  updatedById    String
  createdAt      DateTime                  @default(now())
  updatedAt      DateTime                  @updatedAt

  frontendUser User @relation("FrontendBusinessPreferenceOwner", fields: [frontendUserId], references: [id], onDelete: Restrict)
  updatedBy    User @relation("FrontendBusinessPreferenceActor", fields: [updatedById], references: [id], onDelete: Restrict)

  @@unique([frontendUserId, section])
  @@index([frontendUserId])
  @@index([updatedById])
}
```

表中一行只保存一个分区。`frontendUserId` 永远是主账号的 `dataOwnerId`，`updatedById` 是实际主账号或子账号 ID。数据库迁移只增加枚举、表、外键和索引，不改写现有业务表中的任何行。

电子公章继续作为报告模板的一部分共享。客户端先把图片缩放到最大 `1024 × 1024`，只接受 PNG/JPEG/WebP，再保存为受大小限制的数据 URL；服务端校验 MIME、Base64、图片魔数和解码后字节数。单个公章解码后最大 512 KiB，避免任意 JSON 或超大图片写入数据库。现有 Canvas 报告导出可直接继续使用该值，不引入跨租户公开文件 URL。

## 4. API、校验与并发

新增客户前台接口：

- `GET /frontend-preferences`：按当前账号权限返回可访问分区、版本、更新时间和修改人摘要。
- `PUT /frontend-preferences/:section`：写入一个分区，请求包含 `value` 和 `baseVersion`。

创建首个分区时 `baseVersion=0`；已有分区必须携带读取到的精确版本。服务端在事务内用 `frontendUserId + section + version` 条件更新并递增版本。条件不匹配时返回 HTTP 409 和当前服务器版本，绝不静默覆盖其他主/子账号刚保存的内容。

服务端按分区做结构白名单校验，不接受任意 JSON：

- 报告模板只允许当前标题、来样单位、检验员、审核人、地址、电话、四条声明和公章字段；限制每个字符串和总长度。
- 短信模板只允许前缀和后缀，并限制单项与总长度。
- 来样单位最多 100 个，去空格、去重并限制单项长度。
- 常用组合最多 100 组；名称非空且唯一；元素键必须来自当前 `LabReportElementKey` 白名单；每组去重并按报告元素顺序规范化。
- 路由参数只能是四个固定分区；未知分区返回 400。

接口继续使用现有认证、`FrontendPermissionGuard` 和请求频率/体积限制。后台管理员没有该接口的写权限，后台管理页面不展示电子公章原图或短信模板内容。

## 5. 前端读取、保存与本机旧数据迁移

登录完成后由统一的 `frontendPreferences` 仓库读取服务器配置，并把数据按 `dataOwnerId + section` 缓存到 localStorage。业务页面不再直接读写四个旧的全局 localStorage 键。

正常在线流程：

1. 先显示本机缓存，避免页面空白。
2. 拉取服务器数据后，以服务器版本为准更新缓存和页面。
3. 用户修改时对当前分区防抖保存，携带读取到的 `baseVersion`。
4. 保存成功后更新本地版本；同租户变更通知到达时，干净页面重新读取，正在编辑的页面提示用户处理，不能自动覆盖输入。

首次升级对旧本机数据执行一次性迁移：

1. 如果服务器已经有该分区，直接使用服务器内容，绝不把本机旧数据自动覆盖上去。
2. 如果服务器没有而本机存在非默认旧数据，提示“将本机旧配置同步到当前主账号”或“使用系统默认”；用户确认后才用 `baseVersion=0` 上传。
3. 如果主账号与子账号同时首次上传，只有第一个成功；后续请求收到 409 后加载已经建立的服务器版本。
4. 迁移结果按 `dataOwnerId + section` 记录；退出登录或切换账号不会把一个客户的缓存带给另一个客户。
5. 旧公章数据 URL 在上传前执行图片格式、尺寸和大小检查；不合规时保留本机旧值并提示重新选择图片。

离线或服务器暂时不可用时可以读取已缓存版本并继续生成报告、短信和应用常用组合，但编辑后的服务器共享配置标记为“待同步”，不在恢复网络时静默覆盖。网络恢复后先比较版本；相同版本可提交，不同版本显示本机值与服务器值并要求明确选择“加载服务器内容”或“确认用本机内容覆盖”。

“化验元素当前选择”仍然属于每个样品自己的业务输入；共享的是可反复点击套用的“常用组合”，不能让一个样品的实际元素选择自动改变其他样品。

## 6. 右键编辑与系统剪贴板

桌面主窗口监听 Electron `context-menu` 事件，只根据 Chromium 返回的 `editFlags`、选区和输入框状态构建原生菜单：

- 可编辑区域：撤销、重做、剪切、复制、粘贴、删除、全选。
- 非编辑区域但有文本选区：复制、全选。
- 无选区且不可编辑：不显示空菜单。

各菜单项使用 Electron 原生 `role`，由 Chromium 直接执行，不向远程网页开放 preload、IPC 或剪贴板 API。菜单项是否启用严格跟随 `editFlags`，密码框等 Chromium 禁止复制的场景不会被绕过。macOS 与 Windows 使用同一策略。

网页内“复制短信”继续优先使用浏览器安全剪贴板能力；若系统策略拒绝，调用 `document.execCommand('copy')` 的受控回退。成功或失败只显示一次准确消息。右键和快捷键粘贴由原生编辑角色处理，因此不需要授予远程页面 `clipboard-read` 权限。

## 7. 启动、刷新、离线和崩溃体验

桌面外壳增加可信的本地加载窗口，远程主窗口仍保持无 preload、`nodeIntegration:false`、`contextIsolation:true`、`sandbox:true` 和 `webSecurity:true`。

- 启动时先显示产品图标、产品名和“正在连接服务器”，主窗口保持隐藏。
- 主文档完成加载后关闭加载窗口并显示主窗口。
- 用户执行普通刷新或强制刷新时显示“正在刷新”，完成后回到原页面。
- 15 秒未完成、主文档加载失败、渲染进程崩溃或无响应时进入现有可信离线页，显示错误摘要、重试和退出，不显示技术堆栈。
- 重试重新进入加载状态并加载固定入口；恢复成功后显示主窗口。
- 普通 SPA 页面内部跳转不闪烁加载窗口，只有应用启动、用户主动刷新和故障恢复触发。
- 显示/隐藏加载窗口时同步主窗口当前尺寸和位置，不能出现无主窗口、重复窗口或退出后残留加载窗口。

强制刷新仍执行 `reloadIgnoringCache()`，不会清除 Cookie、登录令牌、IndexedDB、localStorage 或共享配置缓存。

## 8. 标准菜单、查找和缩放

应用菜单补齐平台标准能力：

- macOS 应用菜单：关于、服务、隐藏、隐藏其他、显示全部、退出。
- 编辑菜单：撤销、重做、剪切、复制、粘贴、删除、全选。
- 页面菜单：查找、查找下一个、查找上一个、刷新、强制刷新、实际大小、放大、缩小、全屏。
- 窗口菜单：最小化、缩放/窗口化、前置全部窗口。
- Windows 对应提供应用、编辑、页面和窗口菜单，并使用相同快捷键语义。

页面查找使用只加载本地资源的轻量查找栏，通过单独的最小权限 preload/IPC 调用 `webContents.findInPage()`。远程业务页面仍然没有 preload 或 IPC；查找通道只接收长度受限的字符串、方向和关闭命令，关闭时调用 `stopFindInPage()`。页面缩放限制在 50% 至 200%，关于窗口可一键恢复 100%。

## 9. 版本、安装包和可追溯信息

桌面包版本从 `1.0.0` 升级到 `1.0.1`，Electron 和 electron-builder 版本不变。构建前生成只读构建信息：

- 应用版本。
- UTC 构建时间。
- Git 完整提交号和七位短提交号。
- 构建目标（内部系统/后端系统、macOS/Windows、CPU 架构）。

“关于”对话框显示版本、构建时间和短提交号。构建信息随安装包进入 `resources`，正式打包测试验证它与产物名称一致。

新产物固定为：

- `Yangshao-Internal-System-1.0.1-win-x64.exe`
- `Yangshao-Backend-System-1.0.1-win-x64.exe`
- `Yangshao-Internal-System-1.0.1-mac-arm64.dmg`
- `Yangshao-Backend-System-1.0.1-mac-arm64.dmg`

重新生成 `SHA256SUMS.txt`。覆盖安装不改变现有应用 ID 或 `userData` 目录，因此登录状态和本机草稿保留。本次仍不签名、不公证、不自动更新。

## 10. 测试与验收

每项实现按 RED → GREEN → 回归执行，至少覆盖：

### 服务端

- 主账号与其两个子账号读取同一 `dataOwnerId` 的四个分区，不同主账号严格隔离。
- 客户端伪造 owner ID 无效；实际修改人记录正确。
- 子账号缺少对应叶子权限时 GET/PUT 都返回 403。
- 每个 JSON 结构、数量、长度、元素键和公章格式/大小限制。
- `baseVersion` 创建、更新和两个账号并发写入产生 409，旧数据不丢失。
- 迁移只新增表，不修改现有业务表行。

### 客户前台

- 服务器优先、按 owner 缓存、旧 localStorage 一次性迁移、切换客户不串数据。
- 主账号修改后子账号可见，子账号修改后主账号可见。
- 离线缓存、待同步状态、恢复网络版本冲突和明确覆盖确认。
- 报告模板、公章、短信模板、来样单位快捷名称和常用组合在报告/短信/各样品选择器中一致生效。
- 每个样品的实际元素选择保持独立，应用组合不会改变其他样品。

### 桌面外壳

- 右键菜单按可编辑/选区状态显示，原生复制、粘贴、剪切、撤销和全选可用。
- 远程页面仍无 preload/IPC/Node，权限拒绝和域名校验无回归。
- 启动、普通刷新、强制刷新、15 秒超时、离线重试、渲染进程故障和窗口关闭。
- macOS/Windows 菜单结构、快捷键、查找前后项、关闭查找和 50%–200% 缩放边界。
- 关于信息、版本 `1.0.1`、四个安装包名称、架构、图标和 SHA-256。

### 真机验收

- macOS 13+ Apple Silicon 覆盖安装并确认登录保持、复制短信、右键粘贴、菜单快捷键、启动/刷新加载、断网恢复和四类共享配置。
- Windows 10/11 x64 由内部人员执行同等安装与业务验收。
- 使用一个主账号和两个不同权限子账号交叉编辑，确认权限、共享、冲突提示和审计修改人。

## 11. 发布边界

当前阶段只在本地工作树完成代码、自动测试和本地 macOS 安装包验证，不推送 GitHub、不部署 VPS、不执行生产数据库迁移。待用户明确通知后，才执行代码上传、VPS 备份与迁移审查、生产发布和私有 GitHub Actions 四平台安装包构建。

生产发布必须先备份数据库和代码，检查 Prisma 迁移只包含本设计新增的偏好表，再发布服务端与网页。发布后先验证主账号，再验证子账号共享与隔离；发现异常时停止桌面安装包分发并回滚应用代码，数据库新增空表可保留但不得破坏既有数据。
