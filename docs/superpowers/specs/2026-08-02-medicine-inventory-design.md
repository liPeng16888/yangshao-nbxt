# 药品库存功能设计

## 目标

在前台“报表”和“客户总览”之间增加“药品库存”主功能，并提供“药品库存”“药品入库”“药品出库”三个页面。前台账号只能管理自己的库存；后台只能查询被授权账号的库存及流水，不能修改数据。

库存必须满足以下约束：

- 不同前台账号的数据完全隔离。
- 同名药品在不同账号中可以使用不同单位。
- 单位固定为：瓶、升、毫升、克。
- 同一账号可以建立同名但不同单位的独立库存项，例如“盐酸（瓶）”和“盐酸（毫升）”，二者不自动换算。
- 出库数量超过当前库存时禁止提交。
- 已提交的流水不直接编辑或删除；错误数据通过带原因的反向更正流水处理。

## 方案选择

采用“账号独立药品档案 + 物化当前库存 + 不可变库存流水”的方案。

与只在查询时汇总全部流水相比，物化库存能稳定支撑库存列表和并发出库校验；与只保存当前库存相比，不可变流水能够完整解释每次库存变化。库存数量和流水必须在同一个数据库事务中更新，任何一步失败都整体回滚。

## 数据模型

### MedicineInventoryItem

每一条记录代表某个前台账号的一种“药品名称 + 单位”库存项。

- `id`
- `frontendUserId`
- `name`
- `unit`: `BOTTLE | LITER | MILLILITER | GRAM`
- `currentQuantity`: `Decimal(14, 3)`，默认 `0`
- `createdAt`
- `updatedAt`

约束：

- 唯一键为 `frontendUserId + name + unit`。
- 所有查询和写入必须带当前登录账号范围。
- 前台显示单位中文名称：瓶、升、毫升、克。
- “瓶”的数量只允许正整数；升、毫升、克允许正数并最多保留三位小数。

### MedicineInventoryMovement

每一条记录代表一次不可变的库存变化。

- `id`
- `frontendUserId`
- `medicineItemId`
- `type`: `INBOUND | OUTBOUND | CORRECTION_IN | CORRECTION_OUT`
- `occurredOn`: 业务日期，格式 `YYYY-MM-DD`
- `quantity`: 正数 `Decimal(14, 3)`
- `remark`
- `correctionOfId`: 更正时指向原流水，普通入库/出库为空
- `createdAt`

流水保存当时的药品名称和单位快照，避免未来显示名称变化影响历史查看。更正流水必须填写原因，不修改原始流水。

### User 关系

在 `User` 增加药品库存项和库存流水关系。删除前台账号时沿用系统现有软删除规则，不级联清空药品历史。

## 后端模块与接口

新增独立 `medicine-inventory` 模块，包含 controller、service、DTO 和测试，不把库存逻辑混入财务或数据计算模块。

### 前台接口

- `GET /medicine-inventory/items`
  - 返回当前账号库存。
  - 支持一个或多个 `medicineItemIds` 筛选。
  - 默认按药品名称、单位排序。
- `GET /medicine-inventory/inbounds`
  - 返回当前账号入库和入库更正明细。
  - 支持日期范围及一个或多个药品筛选。
- `POST /medicine-inventory/inbounds`
  - 录入日期、药品名称、单位、数量、备注。
  - 相同“名称 + 单位”复用库存项，不存在时创建。
- `GET /medicine-inventory/outbounds`
  - 返回当前账号出库和出库更正明细。
  - 支持日期范围及一个或多个药品筛选。
- `POST /medicine-inventory/outbounds`
  - 录入日期、已有库存项、数量、备注。
  - 使用数据库事务和条件更新保证扣减后库存不能小于零；不足时返回 `409` 和最新库存。
- `POST /medicine-inventory/movements/:id/corrections`
  - 对错误流水创建反向更正记录，必须填写原因并二次确认。
  - 更正入库相当于扣减库存；若会造成负库存则拒绝。
  - 同一原流水只能完整冲销一次，防止重复更正。

### 后台接口

- `GET /admin/medicine-inventory/items`
- `GET /admin/medicine-inventory/inbounds`
- `GET /admin/medicine-inventory/outbounds`

后台接口支持：

- 一个或多个前台账号筛选。
- 一个或多个药品库存项筛选。
- 入库、出库页支持日期范围筛选。
- ROOT_ADMIN 可查询全部前台账号；SUB_ADMIN 只能查询已授权账号。
- 不提供后台新增、修改、删除或更正接口。

## 前台页面

### 导航与路由

在“报表”和“客户总览”之间增加可展开的“药品库存”：

- `/medicine-inventory/stock`：药品库存
- `/medicine-inventory/inbound`：药品入库
- `/medicine-inventory/outbound`：药品出库

访问设置沿用现有统一访问密码，将 `/medicine-inventory` 作为受保护路径。

### 药品库存

- 顶部使用可清空、多选下拉框筛选一个或多个药品。
- 表格显示药品名称、现有库存、单位、最后变动时间。
- 相同名称不同单位显示为独立行。
- 页面只展示库存，不直接修改数量。

### 药品入库

- 紧凑录入表单包含：入库时间、药品名称、单位、数量、备注。
- 药品名称支持选择已有库存项或输入新名称。
- 选择已有库存项时自动带出并锁定单位；输入新名称时必须选择单位。
- 提交前二次确认，成功后刷新库存与入库明细。
- 下方明细按业务日期倒序、创建时间倒序显示，可按药品及日期筛选。
- 错误记录提供“更正”操作，不提供删除和直接编辑。

### 药品出库

- 紧凑录入表单包含：出库时间、药品名称、当前库存、单位、数量、备注。
- 只能选择已有且库存大于零的库存项。
- 输入数量时即时显示“出库后剩余”，超过库存立即显示错误并禁用提交。
- 提交前二次确认，服务端仍执行最终库存校验。
- 下方明细及更正规则与入库页一致。

## 后台页面

后台侧栏增加“药品库存”，进入后使用三个标签页：

- 当前库存
- 入库明细
- 出库明细

页面顶部保留多账号筛选，并增加多药品筛选。表格增加账号名称列，所有内容只读，不出现新增、修改、删除或更正按钮。

## 数据流与并发

### 入库

1. 校验日期、名称、单位和数量。
2. 在事务中查找或创建当前账号的库存项。
3. 增加 `currentQuantity`。
4. 创建入库流水。
5. 返回最新库存项和流水。

### 出库

1. 校验库存项属于当前账号且数量格式正确。
2. 在事务中执行带条件的库存扣减：`currentQuantity >= quantity`。
3. 条件更新失败时读取最新库存并返回 `409`，不创建流水。
4. 扣减成功后创建出库流水。
5. 返回最新库存项和流水。

这种处理能避免同一账号在两台设备同时出库时产生负库存。

## 错误处理

- 必填项缺失或数量格式错误：`400`，前端定位到具体字段。
- 药品不属于当前账号：`404`，避免泄露其他账号数据。
- 库存不足或并发后库存发生变化：`409`，显示最新库存并保留用户已填写内容。
- 重复更正：`409`。
- 网络或服务器错误：不清空表单，允许用户重试。
- 后台访问未授权账号：按现有后台权限规则过滤，不返回越权数据。

## 数据迁移与部署

- 新增 Prisma 枚举、两张数据表、索引和 User 关系，需要生成增量迁移。
- 迁移只创建新结构，不修改或清空任何现有账号、样品、财务、客户、黑名单或上传数据。
- 不运行 `seed`、`db push --force-reset` 或任何重置命令。
- 当前没有历史药品库存数据，因此迁移后库存表为空，由各账号首次入库建立库存项。

## 测试范围

### 后端

- 不同账号同名药品可以使用不同单位且数据隔离。
- 同一账号同名同单位复用库存项，同名不同单位建立独立库存项。
- 入库同时增加库存和创建流水。
- 正常出库同时扣减库存和创建流水。
- 超库存出库返回 `409` 且库存和流水都不变化。
- 两个并发出库请求不能导致负库存。
- 更正流水可追溯、不可重复，更正入库不能造成负库存。
- SUB_ADMIN 只能查看授权账号，后台接口无写操作。

### 前台

- 导航位置、三个子路由和访问密码保护正确。
- 单药品和多药品筛选正确。
- 新药品必须选单位；已有药品单位锁定。
- 瓶只接受正整数，其他单位最多三位小数。
- 出库超过库存时按钮禁用，服务端 `409` 后显示最新库存且保留表单。
- 更正必须填写原因并二次确认。

### 后台

- 多账号、多药品和日期范围筛选正确。
- 三个标签页数据与前台流水一致。
- 页面不存在编辑入口。

## 非本次范围

- 不做瓶、升、毫升、克之间的自动换算。
- 不与财务支出账单自动关联。
- 不设置最低库存提醒或保质期提醒。
- 不允许后台代替前台修改库存。
