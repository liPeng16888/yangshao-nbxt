# 仰韶化验室系统代码安全审核报告

- 审核日期：2026-08-03
- 审核对象：前端、后台管理端、NestJS API、Prisma 数据模型与迁移、构建配置、依赖锁定文件、测试
- 审核方式：静态代码审查、认证/授权数据流追踪、敏感信息检索、依赖漏洞扫描、测试/类型检查/生产构建
- 代码状态：审核基于当前本地工作区（包含尚未提交的改动），未修改业务或安全代码
- 结论等级：**当前版本不建议直接暴露到公网**

## 1. 执行摘要

本次共确认 15 项安全与工程风险：

| 等级 | 数量 | 结论 |
| --- | ---: | --- |
| 严重（Critical） | 5 | 可造成访问控制绕过、全部账号密码泄露或令牌伪造，应先修复 |
| 高（High） | 4 | 可造成暴力破解、恶意上传、会话泄露或利用已知依赖漏洞 |
| 中（Medium） | 5 | 增大拒绝服务、数据泄露、注册滥用和部署暴露风险 |
| 低（Low） | 1 | 影响安全回归测试的稳定性和可信度 |

最危险的攻击链如下：

1. 攻击者只要取得普通前端账号令牌，就能绕过页面上的“访问密码”，直接请求财务、报表、黑名单、药品库存、客户总览及历史日期接口。
2. 数据库或后台根账号一旦泄露，系统可以解密并显示客户账号的登录密码；访问组合密码和找回答案更是以明文保存并返回浏览器。
3. 如果生产环境遗漏 `JWT_SECRET`，代码会使用公开可猜的 `dev-secret`，攻击者可以自行签发任意用户令牌。
4. 图片上传没有大小、真实文件类型和存储配额限制，且上传结果无需再次鉴权即可公开访问。
5. 生产依赖扫描确认 17 个已知漏洞，其中 8 个为高危，包括 Multer 拒绝服务和 ECharts XSS。

这不等于系统已经被入侵。本次没有发现仓库中的真实 `.env`、私钥、硬编码数据库连接串、明显的原始 SQL 注入、`eval` 或系统命令执行。但上述漏洞使系统在公网环境下容易遭到绕过、撞库、敏感数据窃取和拒绝服务攻击。

## 2. 已确认问题

### SEC-01 严重：访问密码仅在前端路由拦截，多数后端接口可直接绕过

**证据**

- `src/router/index.ts:116-140` 只在浏览器路由切换时弹出访问密码。
- `src/router/guards.ts:19-25` 将财务、报表、黑名单、药品库存和客户总览映射为前端保护项。
- `server/src/finance/finance.controller.ts:15-180`、`server/src/reports/reports.controller.ts:20-39`、`server/src/blacklist/blacklist.controller.ts:16-39`、`server/src/customers/customers.controller.ts:16-29`、`server/src/medicine-inventory/medicine-inventory.controller.ts:37-95` 只校验主登录令牌和角色，没有校验对应的访问授权令牌。
- `server/src/lab-sheets/lab-sheets.controller.ts:50-52` 的历史日期列表也未校验 `HISTORICAL_DATES`。
- 已完成样品的数据隐藏是例外：`server/src/lab-sheets/lab-sheets.controller.ts:17-27,44-47` 已在服务端校验并脱敏。

**攻击方式与影响**

用户登录后可以跳过页面，直接用浏览器开发者工具、脚本或 API 客户端请求受保护接口。访问密码并不能阻止已登录用户读取或修改这些业务数据。

**修改方案**

- 建立统一的 NestJS `AccessGuardFeatureGuard` 和功能装饰器，在所有受保护的控制器/方法上强制校验 `x-ys-access-grant`。
- 服务器先判断该功能是否被加入启用组合；若已保护，则要求授权令牌的用户、组合、功能和有效期全部匹配。
- 历史日期的列表、指定日期读取以及相关写入都必须保护；不能只拦截页面入口。
- 为每个功能增加“无令牌/错误功能/错误用户/过期令牌/正确令牌”的接口测试。

### SEC-02 严重：登录密码被可逆加密保存，并回显给根管理员

**证据**

- `server/src/auth/password.service.ts:15-33` 使用 AES-GCM 可逆加密，且密钥缺失时回退为固定字符串。
- `server/prisma/schema.prisma:83-84` 同时保存 `passwordHash` 与 `passwordCipher`。
- `server/src/admin/accounts.service.ts:26-71,135-157,209-230` 解密密码并返回后台管理端。
- `admin/src/views/AccountManagementPage.vue:29,69` 显示密码。

**攻击方式与影响**

数据库备份、服务器环境密钥、根管理员账号或相关 API 任一处泄露，都可能暴露所有客户当前使用的原始密码。客户若复用密码，还会影响其他网站账号。

**修改方案**

- 保留现有 bcrypt `passwordHash`，立即停止写入和读取 `passwordCipher`。
- 后台只提供“生成临时密码/强制重置密码”，不能查看原密码。
- 数据迁移删除所有 `passwordCipher`；这不会影响现有用户登录，因为登录本来使用 bcrypt 哈希。
- 上线后通知管理员原密码查看功能已取消，并保留密码重置审计日志。

依据：OWASP 建议认证密码使用单向慢哈希而不是可逆加密：<https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html>

### SEC-03 严重：访问组合密码和找回答案明文保存并返回客户端

**证据**

- `server/prisma/schema.prisma:123-132` 的 `password`、`recoveryAnswer` 均为明文字段；旧字段也在 `server/prisma/schema.prisma:85-89` 中明文保存。
- `server/src/auth/auth.service.ts:174-192,226-240` 明文写入和比较密码。
- `server/src/auth/auth.service.ts:280-299` 将密码和找回答案返回浏览器。
- `src/stores/accessGuard.ts:82-87` 在客户端比较找回答案并重置密码。

**攻击方式与影响**

只要取得主账号令牌或通过前端 XSS 执行代码，就能读取所有访问密码及找回答案。所谓“找回验证”实际上不能作为秘密验证，因为正确答案已经下发到浏览器。

**修改方案**

- 访问密码、找回答案都改为 Argon2id 或 bcrypt 单向哈希；响应只返回“是否已设置”。
- 验证、关闭组合和找回验证全部由服务器完成，并增加失败次数限制。
- 更稳妥的找回方式是要求当前主登录密码，或由后台管理员执行重置；不要把安全问题答案发送给前端。
- 迁移期间将所有现有组合标记为“需要重新设置访问密码”，不应尝试继续回显旧值。

### SEC-04 严重：JWT 和密码加密密钥存在固定回退值，配置缺失时仍会启动

**证据**

- `server/src/auth/auth.guard.ts:19`、`server/src/auth/auth.service.ts:232,239,335`、`server/src/lab-sheets/lab-sheet-stream-auth.service.ts:18` 在 `JWT_SECRET` 缺失时使用 `dev-secret`。
- `server/src/auth/password.service.ts:33` 在密钥缺失时使用 `dev-password-cipher-secret`。
- `server/src/app.module.ts:18` 未对必需环境变量设置启动校验。

**攻击方式与影响**

一旦部署时漏配变量，攻击者知道源代码中的默认值后即可伪造 JWT，冒充任意用户。固定密码加密密钥也使可逆保存的密码更容易被批量解密。

**修改方案**

- 删除全部安全密钥回退值；启动时校验 `JWT_SECRET`、数据库连接等必需配置，不合格立即退出。
- 使用密码管理器生成至少 256 位随机 JWT 密钥，并通过部署平台 Secret 注入。
- 修改后轮换密钥并让全部现有令牌失效；不要把真实密钥写入仓库。

### SEC-05 严重：种子脚本包含默认根管理员密码并会重置现有根账号

**证据**

- `server/prisma/seed.ts:8-22` 缺少环境变量时使用 `admin/admin123456`，并通过 upsert 更新现有账号密码。
- `.env.example:6-10`、`server/.env.example:1-5` 也给出相同可预测凭据。

**攻击方式与影响**

误在生产运行种子脚本，或照抄示例配置部署，会产生公开可猜的最高权限账号；重复运行还可能把已经修改过的密码重置为弱密码。

**修改方案**

- 种子脚本在缺少显式强密码时必须失败；已有根账号存在时不得改密码。
- 首次安装生成一次性随机密码，只显示一次并强制首次登录修改。
- 立即核对实际部署根账号是否仍使用示例密码；如是，先人工更换，再改代码。

### SEC-06 高：登录和访问密码验证没有限流、锁定或异常告警

**证据**

- `server/src/auth/auth.controller.ts:13-20,71-75,83-85` 的注册、登录、后台登录和访问密码验证均无节流保护。
- `server/src/auth/dto.ts:20,45,58,103` 主密码最低 6 位，访问密码最低 4 位。

**影响**

攻击者可以持续撞库、枚举弱密码和暴力尝试四位访问密码；bcrypt 本身不能替代请求限流。

**修改方案**

- 按 IP 与账号双维度限流；连续失败后指数退避或短时锁定，并记录安全日志。
- 主密码提高到至少 10–12 位并允许密码短语；访问密码建议至少 6 位，或允许更长密码短语。
- 登录错误信息保持一致，避免泄露账号是否存在。

### SEC-07 高：图片上传缺少大小、真实类型和配额限制，文件公开可读

**证据**

- `server/src/uploads/uploads.controller.ts:14-18` 仅限制最多 10 个文件，没有 `fileSize` 和 `fileFilter`。
- `server/src/uploads/uploads.service.ts:23-58` 信任客户端 MIME 和原始扩展名，不检查文件魔数、不重新编码、无用户配额/病毒扫描。
- `server/src/main.ts:18-19` 将整个上传目录作为匿名静态资源公开。
- `server/prisma/schema.prisma:384-392` 上传记录没有归属用户字段。

**攻击方式与影响**

认证用户可以通过大文件耗尽内存或磁盘，上传伪装文件并利用公开 URL 对外托管；黑名单或财务图片也可能被知道 URL 的人匿名访问。

**修改方案**

- 在 Multer 层限制单文件大小、总大小、文件数；校验文件魔数并只允许 JPEG/PNG/WebP。
- 解码后重新编码图片，剥离 EXIF；拒绝 SVG、HTML 和格式不一致文件。
- 上传记录关联用户和业务对象，改为鉴权下载接口；文件存到 Web 根目录之外。
- 设置每账号配额、过期孤儿文件清理、审计日志和反向代理请求体上限。

依据：OWASP 文件上传指南要求扩展名、内容类型、文件签名、大小、授权和存储位置多层校验：<https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html>

### SEC-09 高：长期 JWT 保存在 localStorage，SSE 又把令牌放入 URL

**证据**

- `src/stores/auth.ts:20,26-31`、`admin/src/api.ts:35-38,490-491` 将令牌写入 localStorage。
- `server/src/auth/auth.service.ts:334-335` 令牌有效期为 7 天。
- `src/api/labSheet.ts:63-72` 把令牌加入 SSE 查询字符串；`server/src/lab-sheets/lab-sheets-stream.controller.ts:14-17` 接受该查询令牌。
- `server/src/auth/auth.controller.ts:29-33` 退出登录没有服务端撤销动作。

**影响与修改方案**

XSS 可直接读取令牌，URL 令牌还可能进入浏览器历史、代理和服务日志。建议改为 HttpOnly、Secure、SameSite Cookie 或“短期访问令牌 + 可轮换刷新令牌”；SSE 使用极短期、一次性票据；实现 `tokenVersion`/JTI 撤销和真正的退出登录。若采用 Cookie，还必须加入 CSRF 防护。

### SEC-10 中：CORS 全开放，缺少常用 HTTP 安全头

**证据**

- `server/src/main.ts:11` 无条件 `enableCors()`。
- 启动代码没有 Helmet/CSP、HSTS、`X-Content-Type-Options`、frame 和 referrer 策略。

**修改方案**

只允许明确的前端和管理端生产域名、HTTP 方法和请求头；在应用或反向代理配置 Helmet/CSP、HSTS、nosniff、frame-ancestors 和 Referrer-Policy。确认全站 HTTPS，HTTP 自动跳转 HTTPS。

### SEC-11 中：多处请求体/查询参数使用 `any`，范围和长度限制不一致

**证据**

- `server/src/finance/finance.controller.ts:23-180`、`server/src/reports/reports.controller.ts:27-32`、`server/src/blacklist/blacklist.controller.ts:27-32`、`server/src/customers/customers.controller.ts:22` 等大量使用 `@Body() body: any` 或 `@Query() query: any`。
- `server/src/main.ts:12-16` 开启 whitelist，但未设置 `forbidNonWhitelisted`；`any` 也绕过 DTO 验证。
- `server/src/auth/dto.ts:4-10` 登录字段无最大长度；访问设置若干可选字段缺少完整类型验证。

**影响与修改方案**

超长字符串、非法日期、非预期枚举和多余字段可能进入业务逻辑，造成资源消耗、异常或脏数据。为所有端点建立 DTO，加入类型、枚举、日期、金额、数组个数和字符串最大长度约束，并开启 `forbidNonWhitelisted: true`。错误响应不要回显内部堆栈。

### SEC-12 中：已登录用户可以触发无上限数据创建或超大报表范围

**证据**

- `server/src/lab-sheets/lab-sheets.controller.ts:39-41` 接受客户端提供的新增样品数量；`server/src/lab-sheets/lab-sheets.service.ts:42-61` 只要求正整数，没有最大值。
- 按日期读取会通过 `ensureSheet` 创建数据，使 GET 请求产生写入副作用。
- `server/src/reports/reports.service.ts:21-33,82-90,127-133` 的自定义日期范围缺少最大跨度；`server/src/common/date.ts:27-35` 会为整个范围生成日期数组。

**修改方案**

限制单次新增数量、每日报表行数、日期跨度和账号存储配额；GET 只读，缺失工作表应由显式 POST 创建；对高成本报表分页或异步生成，并设置超时。

### SEC-13 中：一次性注册码存在并发重复使用窗口

**证据**

- `server/src/auth/auth.service.ts:40-68` 在事务外先查询注册码，再在事务内创建用户并更新；并发请求可能同时通过 `usedAt` 检查。

**修改方案**

在事务中用带 `usedAt: null` 和有效期条件的原子 `updateMany` 抢占注册码，并要求更新数量等于 1；必要时使用可串行化事务，增加并发注册测试。

### SEC-14 中：仓库与本地开发配置可能泄露业务数据或扩大局域网暴露

**证据**

- `凯里化验室数据统计.xlsx` 已被 Git 跟踪，文件名显示其可能包含真实业务数据。
- 根 `package.json:7,14` 和 `admin/package.json:7,9` 将开发/预览服务器绑定到 `0.0.0.0`。
- 管理端 mock 登录逻辑包含 `admin123456`（`admin/src/api.ts:424`）；若 mock 构建误用于共享网络，会产生误授权风险。

**修改方案**

- 人工确认 Excel 内容；如为真实数据，移出仓库并清理 Git 历史，只保留脱敏测试数据。`.gitignore` 增加通用 `.env*` 例外规则和业务文件规则。
- 开发服务器默认绑定 `127.0.0.1`；需要局域网访问时显式开启并配合防火墙。
- 生产构建强制关闭 mocks，CI 检查生产包中不存在 mock 账号和样例密码。

本次为了避免扩大敏感数据接触面，没有打开并读取该 Excel 的业务内容。

### SEC-15 低：测试配置会扫描隐藏工作树/本地缓存，降低安全回归可信度

`vitest.config.ts:12-15` 未排除 `.worktrees`、`.pnpm-store`、`.superpowers`。默认执行在当前机器上会重复扫描这些目录并产生与主工作区无关的失败和巨大日志。本次使用显式排除参数后，主工作区 42 个测试文件、301 项测试全部通过。

建议将上述目录加入 `test.exclude`，并在 CI 固定 Node/pnpm 版本及测试范围。

## 3. 已确认的正面控制

- 主登录密码使用 bcrypt，工作因子为 12（`server/src/auth/password.service.ts:7-12`）。
- `AuthGuard` 每次请求都会重新检查用户是否禁用/删除；多数控制器同时使用角色守卫。
- 后台账号管理接口限制为根管理员；子管理员通过允许的前端账号 ID 做数据范围限制。
- 抽查的数据写入服务普遍以 `frontendUserId` 限定租户，未发现明显的跨账号直接对象引用漏洞。
- Prisma 查询为参数化 API；未发现应用代码中的原始 SQL 拼接、`eval`、`child_process` 或 Vue `v-html`。
