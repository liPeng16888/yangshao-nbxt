# 飞书 AI 接入

管理入口：后台 **AI API 配置 → 飞书接入**。一个企业自建机器人、仅私聊文字和图片；同一飞书使用者可以切换多个网站身份，每个网站账号只允许绑定一位飞书使用者。

## 部署

1. 安装锁文件中的依赖并生成 Prisma Client。官方 SDK 固定为 `@larksuiteoapi/node-sdk@1.74.0`，使用 `WSClient` 的真实握手和重连状态。建议使用 Node.js 24 LTS。
2. 保留已有 `AI_API_KEY_SECRET`（至少 32 字节），不要换成新随机值，否则已有模型密钥无法解密。飞书 App Secret、短时授权和消息队列也使用此密钥加密。
3. 备份数据库，执行 `pnpm --filter yangshao-server prisma:deploy`。迁移 `20261010010000_add_ai_feishu` 只新增频道表与索引，不修改现有业务表和记录。默认关闭。
4. 构建前后台和服务端。服务端实际启动入口为 `server/dist/src/main.js`，已同步修正 `start` 脚本。
5. 网站保持现有同源部署：前台 `/`、后台 `/admin/`、接口 `/api/`。确保两个绑定页面和 `/ai/feishu/access` 都能通过 SPA fallback 加载，并提供可用的 HTTPS 根地址。
6. 以单实例运行 Nest 服务端。数据库租约防止第二个消费者处理同一队列；进程退出时关闭连接和消费者。服务端需要允许访问飞书公网 HTTPS/WSS 接口，无需为机器人暴露入站回调端口。

本地 Vite 默认演示登录，不能连接真实飞书、保存密钥或完成绑定。真实使用需 `VITE_USE_MOCKS=false`、`VITE_ADMIN_USE_MOCKS=false` 并配置正确的 API 代理。不要将其他项目的 3000 端口误当成本项目后端。

## 管理员配置

1. 在 [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用，启用机器人。
2. 申请 `im:message`（消息收发）、`im:resource`（图片资源）权限。不需要通讯录、群聊历史、服务台权限。
3. 在网站“飞书接入”填写 App ID、App Secret、网站 HTTPS 地址，启用并保存。密钥不返回原文；编辑时留空保留原密钥。
4. 到飞书“事件与回调”选择长连接，订阅 `im.message.receive_v1` 与 `card.action.trigger`，创建并发布版本、由企业审批、配置应用可用人员范围。先启动网站连接再选择长连接，可通过平台的连接检查。
5. 在网站测试连接。**已连接只表示握手成功，不代表权限、事件订阅和应用发布均正确。** 使用真实测试人员完成文字、图片和确认卡片往返后再扩大可用范围。
6. 先在“模型与服务”“读取与写入权限”启用账号并授权，选择支持业务工具的默认模型。图片需要该模型的图片能力。

更换 App ID 会使已有邀请、绑定、飞书会话和卡片失效，需要重新邀请。更新同一 App 的 Secret 保留绑定并重连，旧会话失效。停用飞书接入不影响网站 AI；恢复时新建会话。回退时关闭接入，保留新增表与审计，不执行删表回退。

## 绑定与使用

主管理员选择网站账号和默认模型，生成 `绑定 <随机指令>`。指令与证明只保存哈希，10 分钟有效，新邀请使该账号的旧邀请失效。

本人在机器人**私聊**发送指令，打开返回的 HTTPS 验证链接，登录指定的网站账号核对飞书使用者 ID 和模型，点击确认。前后台登录各自使用对应入口；令牌放在 URL fragment，登录过程中仅用当前浏览器的 sessionStorage 延续，不能跳转到任意外部地址。

聊天命令：

| 命令 | 行为 |
| --- | --- |
| 帮助 | 显示绑定方法和命令 |
| 状态 | 显示当前网站身份、数据账号和模型 |
| 切换身份 | 选择本人已验证的绑定；新绑定不自动覆盖已有身份 |
| 切换账号 | 后台身份从当前授权的前台账号中选择数据归属 |
| 新建对话 | 清空飞书上下文、短时授权，使旧确认卡片失效 |
| 访问验证 | 在网站验证原有访问密码，再回飞书重新发送请求 |

文字最多 6000 字符；图片限单条 JPG/PNG/WebP、5MB，走原有附件校验并在 24 小时后过期。语音、文件、群聊和图片相册不在首期范围。所有数据库修改先生成 15 分钟有效的预览卡片，原使用者核对后确认，取消不会写入。大草稿超过卡片容量时提示缩小范围，不生成可误确认的截断卡片。

飞书不会得到管理员代理令牌、数据库凭据、原始 SQL 或额外权限。按绑定的网站身份重新解析当前权限、数据归属、AI 字段授权、模型授权、全局禁止项、访问密码和原有业务约束。网站/飞书共用网站账号每日 AI 请求额度。账号角色或主账号归属变化后需重新绑定。

## 消息可靠性与审计

接收回调先加密持久化并按应用与消息/回调 ID 去重，再异步处理。数据库序号保持接收顺序，单个消费者处理。回复结果保存后独立重发，使用稳定的飞书消息 UUID；发送失败不会重跑 AI 或数据库写入。重试超过六次后标记失败，错误状态显示在配置页。

进程异常重启后，处理到一半的模型任务提示中断，不自动重跑。原写入确认事务仍以草稿 ID 保证幂等；若确认结果尚未送达，使用者应查看当前数据，或重新点击有效卡片取得状态。旧回复发送前再次核验会话与权限，变更后不发送旧数据。

操作记录位于原 AI“操作记录”页签：绑定、配置、访问验证及业务读取/草稿/确认写入均可追溯；飞书业务记录附带来源、绑定、会话及使用者 ID，不记录密码、授权令牌或 App Secret。

## 验证

前后台分别执行 `vue-tsc --noEmit && vite build`；服务端执行 `nest build`。Node 26 原生 Web Storage 与当前 Vitest/jsdom 存在兼容问题，测试使用 Node 24 LTS。

从仓库根执行：

```sh
./node_modules/.bin/vitest run --silent server/src/ai shared/ai admin/src/components/FeishuSettingsPanel.test.ts
FEISHU_TEST_DB_RUNTIME=/private/tmp/yangshao-ai-db.<临时目录>/node_modules node server/scripts/verify-ai-feishu.cjs
```

集成脚本只允许命名受限的临时 PGlite runtime，在 55442 端口创建一次性数据库；从已有业务表结构加上新增迁移开始，验证绑定唯一性、隔离、原业务写入事务、图片、访问授权、消息去重、重试和重启。它不会使用现有业务 DATABASE_URL，也不发送真实飞书消息或模型请求。真实外部往返验证须提供已发布应用和测试使用者。
